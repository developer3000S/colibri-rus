# Qwen3.6-35B-A3B в colibri — Фаза 0 + Фаза 1

Добавьте Qwen3.6 к поэтапному внедрению colibri. **Фаза 0** = преобразование веса + проверка оракула; **Фаза 1** = Gated Attention + механизм C потоковой передачи MoE, уровень DeltaNet пропускается первым как идентификатор.

<a id="为什么这样切"></a>
## Зачем так резать?

Qwen3.6 — это не стандартная MoE, а гибридная архитектура:

```
10 x ( 3 x (Gated DeltaNet -> MoE) , 1 x (Gated Attention -> MoE) )
#   = 40 层。Gated Attention 层 = 索引 i%4==3 (3,7,11,...,39)，共 10 层 = 25%。
#   Gated DeltaNet 层 = 其余 30 层 = 75% (Phase 2 再实现)。
```

Ключевые параметры (с учетом официального `Qwen/Qwen3.6-35B-A3B`):
- скрытый=2048, словарь=248320, слои=40
- **Gated Attention**: q_heads=16, kv_heads=2, head_dim=256, **rope_dim=64** (поворачиваются только первые 64 измерения каждой головы)
- МЭ: n_experts=256, topk=8 (маршрутизация) + 1 акция, inter=512
- Параметры активации ~3В; Полная модель ~35B

Фаза 1 охватывает только 25 % уровня внимания + полный канал потоковой передачи MoE (контейнер/сегментация слов/потоковая передача/KV/маршрутизация пакетов/общий эксперт), **замена уровня DeltaNet идентичным HF-оракулом для выравнивания на уровне токена**. Это изолирует 80 % риска (индивидуальное линейное внимание) от фазы 2.

<a id="本机端到端验证无需-35b-权重"></a>
## Встроенная сквозная проверка (вес 35B не требуется)

Oracle 35B bf16 требует ~70 ГБ, а ноутбук с 24 ГБ не может работать. Используйте **крошечную модель** с таким же макетом, чтобы проверить логику движка:

```bash
cd c
# 1) 造一个 tiny Qwen3.6 形模型 + 直接吐 ref.json (attention_only)
python tools/make_qwen36_tiny.py --out ../qwen36_tiny
#     -> ../qwen36_tiny/  (模型)  + ref_qwen36.json (attention_only 参考)

# 2) 转成 colibri 容器 (专家 int8;Phase1 用 ebits=8 保真)
python tools/convert_qwen36.py --model ../qwen36_tiny --out ../qwen36_tiny_i8 --ebits 8

# 3) 编译引擎 (MinGW / gcc)
make qwen36

# 4) 跑,对 token
SNAP=../qwen36_tiny_i8 ./qwen36.exe 8 8 ref_qwen36.json
#     期望: Matching tokens: N/N
```

Параметры крошечной модели составляют около нескольких МБ, оракул bf16 — всего несколько сотен МБ, а ноутбук на 24 ГБ может легко работать. Согласование доказывает, что вся связь внимания + потоковая передача MoE + маршрутизация пакетов + общие эксперты + пропуск DeltaNet верны.

<a id="真模型流程需要能跑-hf-预言机的机器如-gpu-服务器"></a>
## Процесс истинной модели (требуется машина, на которой может работать HF oracle, например сервер графического процессора)

```bash
# 转换 (建议 ebits=4 给 16GB 本留余量;对齐验证用 ebits=8)
python tools/convert_qwen36.py --repo Qwen/Qwen3.6-35B-A3B --out /data/qwen36_i4 --ebits 4

# 预言机 (在能加载 35B 的机器上跑,attention_only 模式)
python tools/make_qwen36_oracle.py --repo Qwen/Qwen3.6-35B-A3B \
       --out ref_qwen36.json --mode attention_only --max-new-tokens 32

# 引擎 (在 16/24GB 目标机)
SNAP=/data/qwen36_i4 ./qwen36.exe 16 4 ref_qwen36.json
```

`--mode full` Зарезервировано для использования после фазы 2 (полное смешивание).

<a id="容器格式-张量约定"></a>
## Формат контейнера/тензорное соглашение

`convert_qwen36.py` Выведите **фрагментированный каталог Safetensors** («контейнер» colibri — это каталог):
- Плотные веса (embed/attn qkv o/qk_norm/RMSNorm/routergate/shared expert/lm_head/finalnormal) сохраняют исходный dtype (загрузка F32).
- Три матрицы каждого эксперта объединяются в `model.layers.{l}.mlp.experts.{e}.merged_weight`(int8, порядок сращивания **g|u|d**) + `...qs`(шкала f32, порядок gs|us|ds) - **Полностью повторно использовать `load_expert_merged`/`Slot` из olmoe.c, ноль изменений**.
- Поставляется с `qwen36_meta.json`: все эксклюзивные размеры Qwen3.6, необходимые движку (attn head_dim, веревка_dim, группировка MoE, список слоев attn и т. д.). При его отсутствии движок возвращается к `i%4==3` + по умолчанию.

<a id="引擎要点-cqwen36c"></a>
## Основы движка (`c/qwen36.c`)

- `attention()`: Qwen3 GQA + каждая головка q/k_norm(RMSNorm) + **частичный RoPE** (поворачивается только первый размер `rope_dim` каждой головки, остальные остаются неизменными). KV-кэш распределяется согласно `kv_heads`.
- `moe()`:маршрутизация HF Qwen3 MoE - softmax(gate) → дополнительный ограниченный группой top-k (`n_group`/`topk_group`) → нормализация веса → взвешенная сумма экспертов маршрутизации → **плюс нераспределенные общие эксперты** (SwiGLU). Дополнительный уклон маршрутизатора (`e_score_correction_bias`).
- `step()`: пройти 40 слоев, **`is_attn[i]==0`(DeltaNet) перейти напрямую → Идентичность**. Предварительная выборка пилот-сигнала срабатывает только для «следующего уровня также задействован».
- Экспертная потоковая передача с диска + LRU + поток предварительной выборки PILOT + горячее исправление HOT: тот же набор, что и olmoe (`PILOT/HOT/WARMUP/WIDE/SMOOTH/CONF_LIMIT` переменные среды).

<a id="必须人工核对的项"></a>
## Элементы, которые необходимо проверить вручную

`convert_qwen36.py` Считайте все размеры из `config.json` + заголовок предохранителей и распечатайте. После запуска преобразования **убедитесь, что `qwen36_meta.json` эти значения соответствуют официальным значениям, указанным выше**, особенно:
- `attn.head_dim`(должно быть 256), `attn.rope_dim`(должно быть 64)
- `moe.n_group`/`moe.topk_group` (Официально не заявлено, скрипт конвертации по умолчанию `n_group=1`; если в конфигурации ВЧ есть `n_group`/`topk_group`, он будет принят автоматически, иначе групповой маршрутизации не будет)
- `moe.has_bias`(в том числе `e_score_correction_bias`)

Если `rope_dim` преобразуется в резервное значение `head_dim/4`, вам необходимо подтвердить реальное имя размера каната в конфигурации (пробовал `rope_dim`/`rotary_emb_dim`/`qk_rope_head_dim`).

<a id="已知限制-下一步"></a>
## Известные ограничения/Дальнейшие шаги

- Уровни DeltaNet (75%) идентичны на этапе 1. - **Проверяйте только подмножество уровней внимания**, а не всю модель.
- Не реализовано: 27-слойный визуальный кодер ViT, спекулятивная головка MTP (оба находятся на последующих стадиях).
- **Фаза 2**: реализация Gated DeltaNet на чистом C (рекурсивное состояние + дельта-правило + управление воротами), сначала выровняйте крошечный, а затем получите доступ, затем замените `continue` в `step()` реальным прямым DeltaNet и переключите оракул на `--mode full`.

<a id="校验门"></a>
## Проверьте ворота

После любого изменения: перезапустите крошечный процесс **`Matching tokens: N/N` (по крайней мере, все первые несколько токенов успешны)**. Жадная генерация чувствительна к ошибкам квантования, все совпадения должны быть `ebits=8`; `ebits=4` может смещаться после нескольких токенов (это ожидаемо и будет ослаблено с помощью KL/недоумения позже).
