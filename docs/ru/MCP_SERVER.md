# Сервер MCP: установите и запустите colibri с помощью AI-помощника

colibri отправляет сервер [Model Context Protocol](https://modelcontextprotocol.io),
чтобы помощник по кодированию с помощью искусственного интеллекта мог определить оборудование, порекомендовать модель, установить
его, а также запускать, проверять и останавливать сервер с помощью вызовов инструментов вместо оболочки.
команды. Это тот же код `coli setup` (`c/setup_flow.py`), написанный
только со стандартной библиотекой Python: кроме Python 3.10 устанавливать нечего.

Путь оболочки для помощников без MCP — [AI_SETUP.md](AI_SETUP.md).

<a id="run-it"></a>
## Запусти это

Транспорт — stdio: клиент запускает процесс и обменивается JSON-RPC.
2.0 сообщений с ним, по одному на строку. Любая форма работает:

```bash
python3 /path/to/colibri/c/coli mcp
python3 /path/to/colibri/c/mcp_server.py
```

После `make install` пусковая установка находится на ПУТИ и `coli mcp` достаточно.

<a id="client-configuration"></a>
## Конфигурация клиента

Большинство клиентов MCP принимают запись JSON такой формы (файл и файл верхнего уровня).
ключи различаются в зависимости от клиента; см. его документацию, где он находится). Используйте абсолютный
пути.

Linux, macOS, WSL:

```json
{
  "mcpServers": {
    "colibri": {
      "command": "python3",
      "args": ["/home/me/colibri/c/coli", "mcp"]
    }
  }
}
```

Windows:

```json
{
  "mcpServers": {
    "colibri": {
      "command": "py",
      "args": ["-3", "C:\\Users\\me\\colibri\\c\\coli", "mcp"]
    }
  }
}
```

Необязательная среда в объекте `"env"` рядом с `"args"`:

| Переменная | Использование |
|---|---|
| `COLI_SETUP_HOME` | где хранятся конфигурация запуска, состояние и журналы (по умолчанию: `~/.local/share/colibri`, `~/Library/Application Support/colibri`, `%LOCALAPPDATA%\colibri`) |
| `HF_TOKEN` | токен для закрытых репозиториев моделей |
| `HF_ENDPOINT` | зеркало модели хаба |

Клиент, который принимает только командную строку: `python3 /home/me/colibri/c/coli mcp`.

<a id="tools"></a>
## Инструменты

| Инструмент | Аргументы | Возврат |
|---|---|---|
| `detect_hardware` | `target_dir` (необязательно) | Общее количество и свободное количество оперативной памяти, свободный диск в `target_dir` (по умолчанию `~/colibri-models`) с предупреждением WSL `/mnt/<drive>`, именем и функциями CPU, устройством Vulkan, которое будет использовать движок (тип, бюджет памяти), картами NVIDIA и текстом `summary` |
| `recommend_models` | `target_dir`, `include_unfit` | подходящие модели, каждая с `download_gb`, `ram_min_gb`, `ram_good_gb`, `dense_gb`, `status`, `reason` и идентификатором `recommended`; `fits_means` объясняет, что означает примерка |
| `install` | `model`, `target_dir`, `model_dir`, `backend` (`auto`, `cpu`, `vulkan`, `cuda`), `port`, `start` (по умолчанию true), `wait_seconds` (по умолчанию 0) | запускает фоновое задание `coli setup --yes` и возвращает его pid и журнал; с `wait_seconds` он так долго ждет и сообщает о прогрессе |
| `start` | `open_browser` (по умолчанию false), `wait_seconds` | запускает настроенный сервер в фоновом режиме; возвращает свое состояние и URL-адреса |
| `stop` | нет | останавливает настроенный сервер и его движок |
| `status` | нет | конфигурация (модель, движок, серверная часть, среда), ход установки, состояние сервера (`stopped`, `loading`, `ready`), браузер, URL-адреса OpenAI и Anthropic, API `model_id`, tok/s последнего ответа |
| `logs` | `which` (`server`, `install`, `build`), `lines` | хвост этого бревна |

Результаты переносят данные дважды: в виде текста JSON в формате `content` и в виде
`structuredContent`. Инструмент, который не может сделать то, что просили, возвращает результат
с `isError: true` и причиной (например, `start` перед тем, как что-либо будет
установлено); некорректные вызовы получают ошибку JSON-RPC (`-32602` для неизвестного инструмента
или плохой аргумент, `-32601` для неизвестного метода).

<a id="the-install-job"></a>
### Работа по установке

Загрузка занимает от нескольких минут до нескольких часов, дольше, чем должен блокироваться вызов инструмента. `install`
поэтому запускает установку как отдельный процесс, который продолжает работать, если
помощник или этот сервер завершает работу и сразу возвращается. Следуйте за ним с помощью `status`:
`install.phase` — это `build`, `download`, `ready`, `started` или `error` с
`install.message`; во время загрузки `install.done` и `install.total` являются
байты. Во втором `install`, пока один бежит, отказывают. Снова звоню на номер `install`.
после ошибки или прерывания возобновляется: готовые файлы сохраняются, частично
они продолжаются.

При наличии `wait_seconds` и `progressToken` в `_meta` запроса вызов
отправляет `notifications/progress` во время ожидания (байты во время загрузки,
количество шагов до этого).## Типичная сессия

1. `detect_hardware`, затем `recommend_models`.
2. Сообщите пользователю рекомендуемую модель, размер ее загрузки и куда она идет;
   спросите перед загрузкой.
3. `install` с выбранным `model`. Опрос `status` до `install.phase`
   `started` (или `ready` с `start: false`).
4. Если `logs` с `which: "install"` показывает строку `использовать графический процессор через...,
   первый запуск: <command>`, графическому процессору нужен пакет: покажите команду пользователю,
   и после того, как они его установят, снова позвоните на `install` с тем же `model`.
5. `status`, пока `server.state` не станет `ready`, затем дайте пользователю
   `server.urls.browser` и для других приложений `server.urls.openai_base_url`,
   `server.urls.anthropic_base_url` и `server.model_id`.
6. `stop`, когда пользователь закончил.

<a id="a-typical-session"></a>
## Детали протокола

- Версии протокола `2025-06-18`, `2025-03-26` и `2024-11-05`; сервер
  отвечает версией клиента, если он ее поддерживает, в противном случае — самой новой.
- Возможности: `tools`. Список инструментов не меняется во время выполнения.
- стандартный вывод передает только сообщения протокола; диагностика переходит в stderr, с префиксом
  `[colibri-mcp]`.
- Запросы обрабатываются одновременно: долгое ожидание `install` или `start` не требуется.
  блок `status` или `ping`.
- Когда стандартный ввод закрывается, у вызовов в режиме ожидания есть до минуты на ответ, затем
  процесс завершается. Фоновые установки и запущенные серверы продолжают работать.

<a id="protocol-details"></a>
## Тесты

`c/tests/test_mcp_server.py` управляет протоколом (инициализация, инструменты/список,
инструменты/вызов, ошибки, прогресс) в процессе и через дочерний процесс над реальным
стандартный ввод и стандартный вывод. Вручную:

```bash
printf '%s\n' \
  '{"jsonrpc":"2.0","id":1,"method":"initialize","params":{"protocolVersion":"2025-06-18","capabilities":{},"clientInfo":{"name":"t","version":"0"}}}' \
  '{"jsonrpc":"2.0","id":2,"method":"tools/call","params":{"name":"status","arguments":{}}}' \
  | python3 c/coli mcp
```
