# CACHE_ROUTE — включение маршрутизации MoE с учетом кэша

**По умолчанию: ВЫКЛ.** Стандартное полное поведение маршрутизатора top-K, кроме `CACHE_ROUTE=1`.

Выбор максимального ранга в бумажном стиле (arXiv:2412.00099): всегда сохраняйте верный топ-`J`;
заполните оставшиеся места, отдавая предпочтение экспертам, уже **резидентным** (штырь ∪ LRU), которые
по-прежнему занимает место в топ-`M`.

Это **сторона маршрутизации** (можно изменить список запускаемых экспертов). В дополнение к
**PILOT** (предварительная выборка весов на следующем уровне; идентификаторы экспертов не изменяются).

<a id="engines-and-residency-levels"></a>
## Движки и уровни резидентности

| движок | «резидент» означает | уровни |
|---|---|---|
| `colibri` (GLM-5.2) | в наборе контактов или в кэше LRU RAM | один |
| `qwen36` | на экспертном уровне VRAM (CUDA/Vulkan), остальное в кэше LRU RAM | два: сначала VRAM, затем RAM |

В `qwen36` заполнен слот за священным верхом-`J`, внутри верха-`M`.
окно, созданное экспертом-резидентом VRAM с самым высоким рейтингом, а затем экспертом с самым высоким рейтингом
Резидентный RAM, затем обычный рейтинг. Если уровень не включен, уровень VRAM
пуст, и рычаг переходит в одноуровневое поведение GLM. Ручки
и счетчики одинаковы в обоих движках; нижний колонтитул `qwen36` дополнительно
делит количество свопов на `N to VRAM`.

Единственные заменяемые слоты — это ранги `J..K-1`. На модели, которая маршрутизирует
top-2, значение по умолчанию `ROUTE_J=2` не оставляет ничего для замены и нижний колонтитул
отчеты `swap 0.0%`; ниже `ROUTE_J` к торговому соглашению за попадания.

<a id="flags"></a>
## Флаги

| Окружение | По умолчанию | Значение |
|-----|---------|---------|
| `CACHE_ROUTE` | `0` | `1` = заполнение с учетом кэша максимального ранга (предпочтительно контакт ∪LRU) |
| `ROUTE_J` | `2` | Всегда берите настоящий top-J (даже если он не кэширован) |
| `ROUTE_M` | `12` | Окно максимального ранга для предпочтений резидентов |
| `ROUTE_P` | `0` | Дополнительное окно совокупной массы (`0` = используйте фиксированное M) |
| `ROUTE_ALPHA` | `1` | Масштабировать массу *замененных* экспертов перед изменением нормы (`1` = выкл.) |
| `ROUTE_AGREE` | авто | % перекрытия + KL против истинного top-K; автовключение при `CACHE_ROUTE=1` |

<a id="one-liners"></a>
## Однострочники

```bash
# Stock full-K (leaderboard-comparable routing)
CACHE_ROUTE=0 ./coli chat

# Experimental CACHE_ROUTE
CACHE_ROUTE=1 ROUTE_J=2 ROUTE_M=12 ./coli chat

# Wider prefer window (more hit, more possible swap)
CACHE_ROUTE=1 ROUTE_J=2 ROUTE_M=16 ./coli chat
```

<a id="stats"></a>
## Статистика

Нижний колонтитул/подача `STAT`, когда включено:

- `swap N%` / `swap_pct` — доля выбранных слотов, не входящих в настоящий топ-К
- `route_swaps` / `route_slots` — счетчики необработанных замен
- `route_agree` — |выбрано ∩ true top-K| / К
- `route_kl` — массовый КЛ (истинный топ-К против избранного)
- `hit N%` — попадание в экспертный кэш (резидентность диска)
- `N to VRAM` (только `qwen36`) — сколько из свопов попало на резидентного эксперта уровня

<a id="ab-vs-pilot"></a>
## A/B против ПИЛОТА

```bash
# A: cache-aware routing only
CACHE_ROUTE=1 PILOT=0 ...

# B: lookahead prefetch only (does not change expert IDs)
CACHE_ROUTE=0 PILOT=1 ...

# C: both
CACHE_ROUTE=1 PILOT=1 ...
```

<a id="scope-of-this-pr"></a>
## Объем данного PR

**Только маршрутизация** + телеметрия + это примечание. **Не** требует CUDA/fuse/device-tier
патчи — потоковой передачи CPU + pin/LRU достаточно для A/B рычага против PILOT / #119.

Порт `qwen36` сохраняет эту форму: `route_select()` является чистой функцией
строка softmax, маска группы и обратный вызов резидентности, закрепленные
`tests/test_qwen36_cache_route.c` без модели. При снятом рычаге
Маршрутизатор запускает исходный цикл top-K и выдает байт-идентичные идентификаторы токенов.

Рассматривать как экспериментальный до тех пор, пока не пройдут контрольные параметры качества (например, `./coli bench`); не делай
по умолчанию `CACHE_ROUTE=1`.
