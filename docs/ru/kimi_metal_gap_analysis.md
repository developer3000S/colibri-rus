<a id="metal-layer_decode-attention-kernels"></a>
### Металл `layer_decode` Внимание ядра

Слой объединенного декодирования (`coli_metal_layer_decode`) кодирует внимание в реальном времени через
`encode_attention()`, который отправляет циклы для каждого полушария. Это не отдельные
конвейеры — они закодированы в тот же командный буфер, что и цикл по 96
полголовки (каждая половина головки равна 64 димам для эквивалента KDA/MLA). Ядра
используемые компилируются во время выполнения через исходные строки `MTLLibrary`, встроенные в
тело функции. Они обрабатывают:

- RMSNorm входов Q и KV
- RoPE/NoPE через `generate_rope_phase()`
- Q×декодированный-КВ (поглощение)
- Причинный софтмакс
- Декодирование контекста (скрытое + полное)
- О-проекция с сигмовидными воротами

<a id="key-gap-fmt7-mxfp4"></a>
### Ключевой разрыв: fmt=7 MXFP4

Vulkan поддерживает MXFP4+int8 через `fmt=7` в `coli_vk_matmul` и `coli_vk_pair`.
Металл сегодня **не** поддерживает `fmt=7` — только fmt=1/2/3/4. Это означает,
Экспертные веса W1/W2/W3 MXFP4 не могут работать на Metal и возвращаются к процессору.

## Сводка пробелов

<a id="critical-blocks-full-metal-inference"></a>
### Критический (блокирует полный вывод о Металле)1. **Внимание KDA** — отсутствие металлического ядра ни для одного из 96 конв4, рецидивов, распада или
   О, проекция. Все 69 уровней KDA работают на процессоре.
2. **Внимание MLA (без предохранителя)** — `coli_metal_layer_decode` охватывает только S1 (декодирование,
   один токен). Предварительное заполнение (S>1, пакетное MLA) и встроенные ядра для каждой головы
   не были извлечены в автономный API `coli_metal_mla_forward()`.
3. **MXFP4 matmul** — Металл `mm_gemv` не включает `fmt=7`. В Vulkanе это есть.
4. **rmsnorm_, SiTU-`g` — ядро ​​No Metal для автономного RMSNorm на произвольных тензорах.
   Конвейер `g_a_rms` существует, но его можно вызвать только внутри `layer_decode`.
5. **res_mix (AttnRes)** — ядро ​​без Metal для микса softmax с блочными снимками.
6. **Выборка** — без softmax + top-p + температуры графического процессора, превышающей 262 тыс. слов. Тривиальный матмуль, но не реализованный.

<a id="important-performance-blockers"></a>
### Важно (блокировщики производительности)

7. **Отдельная оболочка matmul** — `coli_metal_matmul()` существует и работает, но
   У `kimi_k3.c` нет диспетчерской `#ifdef COLI_METAL`, чтобы позвонить ему из `w_matmul()`.
   Движок GLM (`colibri.c`) имеет эту отправку; К3 нет.
8. **Плотный вперед** — 24 слоя MLA используют `dense_forward` (3 матмул + SiTU-GLU).
   Металлической оболочки не существует.
9. **Направиться вперед** — Final res_mix + RMSNorm + lm_head. Нет металлической дорожки.
10. **Conv4 + SiLU** — обновление состояния конв. KDA. Нет ядра графического процессора.

<a id="lower-priority"></a>
### Низкий приоритет

11. **Внедренный поиск** — строка с произвольным доступом, считываемая из защитных тензоров. Тривиально для графического процессора
    но в любом случае связан с вводом-выводом.
12. **Выделение/запись кэша KV** — распределение на стороне CPU. Можно перенести в единую память.
13. **L2 нормализовать** — используется в KDA для q/k. Небольшое ядро, но с поддержкой KDA.

<a id="critical-path-to-9393"></a>
### Критический путь к 93/93

Самая эффектная реализация — **MXFP4 matmul (`fmt=7`)** в Metal.
Каждый экспертный уровень Kimi K3 использует веса MXFP4 для W1/W2/W3. Без этого, эксперт
вычисления возвращаются к процессору. После добавления `fmt=7` существующий `mm_gemv`,
Конвейеры `moe_gemv` и `moe_block` могут охватывать все экспертные матмулы с минимальными затратами.
дополнительный код — логика форматирования уже есть, просто нужен новый
шаблон деквантования.
