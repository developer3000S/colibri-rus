# Протоколы обслуживания — формат соединения движка ⇄ сервера

Движок поддерживает два линейно-ориентированных протокола через стандартный ввод/вывод. Оба являются обычным текстом
плюс кадры полезной нагрузки с подсчетом байтов; каждая исходящая строка записывается с завершающим символом
`fflush`, одна строка на запись. В Windows оба конца канала переключаются на двоичный режим.
режим при запуске — в противном случае трансляция CRLF CRT повреждает дозорные и
останавливает чтение с подсчетом байтов (#195).

| протокол | запись | выбрано | используется |
|---|---|---|---|
| **мультиплексор** (непрерывное группирование, до 16 кВ слотов) | `run_serve_mux` | `SERVE_BATCH=1` | `openai_server.py`, `coli web` |
| **устаревшее** (один слот, интерактивный) | `run_serve` | `SERVE=1` (без `SERVE_BATCH`) | `coli chat` |

Этот документ представляет собой справочник по протоколу **mux**; устаревший протокол
подведены итоги в конце. Нижеприведенные форматы строк взяты из излучающих `printf`s в
`glm.c` — если этот документ и код не совпадают, код выигрывает и этому файлу нужен PR.

<a id="startup-handshake-engine-server"></a>
## Рукопожатие при запуске (движок → сервер)

```
\x01\x01READY\x01\x01
CAPS vision=<0|1>
STAT 0 0.00 0.0 <rss_gb>
HWINFO <cores> <ram_total_gb> <ram_avail_gb> <ngpu> <vram_total_gb> <cpu_name>|<gpu_name>
TIERS <vram_experts> <ram_experts> <disk_experts> <vram_gb> <ram_gb>
EMAP <rows> <cols> <hex>
```

Сервер не должен отправлять запросы до `READY`. `HWINFO`/`TIERS`/`EMAP` являются
телеметрии (см. ниже) и может расти — **серверы должны игнорировать типы линий, которые им не нужны.
признать**; это правило прямой совместимости протокола.

`CAPS key=value ...` не является обязательным и находится *между* `READY` и `STAT`: оно говорит, что
движок фактически загрузился, и сервер считывает его, ожидая `STAT`, поэтому
условия обслуживания известны до первого запроса. Сегодня один ключ — `vision`.
(`1`: обзорная башня загружена; `0`: нет — контрольная точка только для текста или конфигурация, которая
объявляет башню, тензоры которой отсутствуют в контейнере). Движки, которые ничего не говорят
оставьте флаг сервера неизвестным. glm53, qwen38, qwen36 и deepseek_v41 испускают его;
`openai_server.py` происходит от `/v1/models` `input_modalities`.

Еще два ключа говорят, какой движок отвечает. `decide=1`: движок берет
`DECIDE` (ниже), и шлюз отправляет ему `POST /v1/systemone` как одну запись
вместо того, чтобы оценивать варианты через канал logprob. `chat=0`: в нем ничего нет
иначе, поэтому генерирующие конечные точки отвечают на 400 указателем на `/v1/systemone`.
Механизм принятия решений (laya, gliner_decide) говорит `decide=1 chat=0`; движок, который общается, а также
решает изначально, говорит только `decide=1` (qwen36 с головой Клефа). `decide_record=raw`
запрашивает запись в необработанном виде, собственные значения вызывающего абонента (docs/systemone.md,
«Движки принятия решений»).

Движок, который не может загрузить свою модель, говорит «почему» по этому каналу вместо
`READY` и выходит:

```
LOAD_FAIL kind=<nomem|io|format|unsupported> <detail>
```

Это последняя строка, которую пишет такой движок. `nomem`: хост отказался от памяти
(ENOMEM/EAGAIN из malloc, mmap или mlock); `io`: файл не доступен или
читать (ENOENT, EACCES, EIO, ...); `format`: файл прочитан, но это не то, что есть
претензии (короткое чтение, плохой заголовок); `unsupported`: правильно сформированный, но dtype или геометрия
этот движок не обслуживается. Деталь — это тот же текст, который написал движок.
стандартный. `openai_server.py` поднимает `EngineLoadError(kind, detail)` и логирует
`[gateway] engine load failed: kind=<kind> <detail>`; движок, который выходит без
такая строка по-прежнему отображается как «движок colibri неожиданно выключился». Общий
путь безопасных тензоров (`st.h`, каждое семейство) излучает его через `coli_load_fail()`
(`load_fail.h`); собственные отказы во время загрузки в семье принимают тот же вызов, что и они
коснулся.

<a id="requests-server-engine"></a>
## Запросы (сервер → движок)

```
SUBMIT <id> <slot> <bytes> <max_tokens> <temperature> <top_p>\n<payload>\n
IMAGE <id> <bytes> <grid_h> <grid_w>\n<payload>\n
STOP <id>\n
CANCEL <id>\n
DECIDE <id> <slot> <bytes>\n<payload>\n
```

- `id` — ненулевой u64, уникальный среди текущих запросов.
- `slot` — индекс слота KV, `0 … KV_SLOTS-1` (`KV_SLOTS` env, 1–16, по умолчанию 1). Слот
  держит КВ одного разговора; движок сопоставляет токенизированную полезную нагрузку систорию слота и повторно использует общий префикс (усечение и расширение), поэтому без сохранения состояния
  HTTP-очереди сохраняют свой кеш. При `KV_SLOTS` выше 1 каждый текстовый движок принимает
  `SUBMIT` в свободном слоте, пока другие декодируют: его подсказка заполняется сразу, и
  с этого момента на каждом этапе декодирования выполняется одна строка для каждого активного запроса. Кадры
  запросы чередуются, каждый помечен своим `id`. `SUBMIT` на слоте,
  запрос все еще выполняется, получает `ERROR <id> SLOT_BUSY`; слот вне диапазона,
  `ERROR <id> invalid cache slot`.
- `bytes` — точная длина `payload` (UTF-8, может содержать символы новой строки). Движок
  читает ровно столько байтов после строки заголовка, а затем один завершающий `\n`.
- `payload` — полностью отрисованное промпт (шаблон чата принадлежит серверу).
- `IMAGE` (GLM-5.3-Flash) объявляет предварительно извлеченные патчи одного изображения для
  запрос с тем же `id` и должен поступить непосредственно перед его
  `SUBMIT`. `payload` — это `bytes` прямого порядка байтов f32 в патче башни
  порядок; сервер владеет предварительной обработкой (`c/tools/glm53_image.py`).
  Подсказка уже должна содержать один заполнитель `<|image|>` для каждого выходного токена,
  т. е. `(grid_h/merge) x (grid_w/merge)` из них: движок отказывается от несоответствия
  вместо того, чтобы отвечать о другой картинке. Движок держит одно в ожидании
  изображение и отбрасывает более раннее.
- `STOP` завершает генерацию по обычному успешному пути `DONE`. Статистика,
  история использования и состояние KV сохраняются; HTTP-шлюз использует его после
  совпадения стоп-последовательности, предоставленной клиентом.
- `CANCEL` прерывает запрос после отключения клиента и возвращает `CANCELLED`.
  Однослотовый текстовый опрос Qwen3.6 для управления опросами между уровнями CPU
  (что бы ни запускало его матрицы и эксперты: экспертный уровень Vulkan или CUDA),
  сохранение всех свежих строк подсказки в пакетном режиме без добавления проходов по частям строк
  потоковые эксперты и между двумя частями быстрых сообщений на Vulkan и CUDA
  цепи. Прерванное промпт отбрасывает свой активный префикс, текущее состояние и
  сохраненные пины; следующий запрос пересчитывается из чистого состояния. контроль
  полученный после полного предварительного заполнения, сохраняет этот действительный префикс. Время ответа
  зависит от одного полного уровня подсказок (или одного фрагмента) работы, а не от фиксированной
  граница миллисекунды. Повороты изображений, подсказки журналов, дампы слоев, qpack и
  `KV_SLOTS>1` сохраняют существующую обработку предварительного заполнения целиком. Журналы шлюза
  клиент, который уходит в середине хода (читая подсказку или генерируя), и
  момент, когда движок освобождает слот.
- `DECIDE` (только для движка, объявившего `decide=1`) принимает одно решение
  запись, UTF-8 JSON: состояние и набранные вопросы с их вариантами в
  заказ. Движок отвечает одним кадром `DECISION` и `DONE` или
  `ERROR <id> DECIDE_INVALID <reason>` за запись отказывается (клиент
  422; причина начинается с поля, `questions.<id>: ...`) и
  `ERROR <id> DECIDE_FAILED <reason>` за собственную неудачу. Рекорд и
  ответ указан в [docs/systemone.md, Механизмы принятия решений](systemone.md#decision-engines);
  `c/decide_serve.h` анализирует один и записывает другой.
- EOF на стандартном вводе = плавное завершение работы: текущие запросы завершаются первыми.

Префилл серийный; декодирование выполняется непрерывно пакетно — каждый активный слот вносит свой вклад
по одному ряду на каждого вперед.

<a id="responses-engine-server"></a>
## Ответов (движок → сервер)

По запросу, по порядку:

```
DATA <id> <n>\n<n bytes of UTF-8>\n        # a decoded token's text; repeated
TOOL <id> <n>\n<n bytes of UTF-8>\n        # engine-authenticated tool structure; Kimi K3 only
TOPK <id> 5 <logprob> <hextext> ... ×5     # candidates for the sampled token (SERVE_TOPK=1)
HITS <rows> <cols> <hex>                   # ~every 6 tokens: routed-expert bitmap since last HITS
REPIN <layer> <eid> <old_tier> <gpu>       # live re-pin swap events, as they happen
...
DONE <id> STAT <emitted> <tok_s> <hit_pct> <rss_gb> <prompt_tokens> <length_limited>
```

и для `DECIDE`:

```
DECISION <id> <n>\n<n bytes of JSON>\n    # once
DONE <id> STAT 0 <tok_s> 0.0 <rss_gb> <tokens_read> 0
```

Kimi K3 отправляет нулевой байтовый кадр `TOOL` сразу после `ACCEPT` для каждого
запрос в чат. Этот фрейм объявляет боковую полосу авторитетной, даже если нет инструмента.следует звонок. Реальная структура специального токена K3 и использование вложенной в него полезной нагрузки инструмента
последующие кадры `TOOL`; обычный декодированный текст остается на `DATA`, поэтому текст, который
только напоминает маркер XTML, который нельзя повысить до вызова клиентского инструмента.

Ошибки заменяют поток: `ERROR <id> <CODE>` на коды `BAD_FRAME`, `BAD_REQUEST`,
`SLOT_BUSY`, `DUPLICATE_ID`, `EMPTY_PROMPT`, `NOT_FOUND` (ОТМЕНА неизвестного идентификатора),
`CANCELLED`, а для механизмов принятия решений `DECIDE_INVALID`, `DECIDE_FAILED` и
`NOT_SUPPORTED` (`SUBMIT` для движка, который не генерирует). `CANCEL` подтверждается `ERROR <id> CANCELLED` после KV слота.
сохраняется.

Непосредственно перед каждым `DONE` движок выдает блок телеметрии о готовом
поворот: `HWINFO`, `PERF`, `ENTROPY`, `GPUS`, `TIERS`, `EMAP`, `HITS` (форматы ниже).
`.coli_usage` сохраняется в конце каждого хода, а не только при выходе.

<a id="telemetry-lines"></a>
## Линии телеметрии

| линия | формат | смысл |
|---|---|---|
| `TIERS` | `TIERS <vram> <ram> <disk> <vram_gb> <ram_gb>` | количество экспертов на уровень + резидентные байты |
| `HWINFO` | `HWINFO <cores> <ram_total> <ram_avail> <ngpu> <vram_total> <cpu>\|<gpu>` | снимок хоста (гигабайты — числа с плавающей запятой) |
| `CAPS` | `CAPS key=value ...` | только рукопожатие, между `READY` и `STAT`: что загружено в движок (`vision=0\|1`) |
| `LOAD_FAIL` | `LOAD_FAIL kind=<kind> <detail>` | только рукопожатие, вместо `READY`: почему модель не загрузилась (`nomem`, `io`, `format`, `unsupported`); после этого движок выключается |
| `EMAP` | `EMAP <rows> <cols> <hex>` | один байт на эксперт, по строкам более `rows×cols` (разреженные слои +MTP × эксперты): `byte = (tier<<6) \| heat` — 2-битный уровень (0 дисков / 1 ОЗУ / 2 видеопамяти), 6-битный уровень использования с распределением по журналам₂ |
| `HITS` | `HITS <rows> <cols> <hex>` | 1 бит на эксперта, эксперты перенаправлены с предыдущего `HITS` |
| `PERF` | `PERF <id> <dt> <t_edisk> <t_ewait> <t_emm> <t_attn> <t_kvb> <t_head>` | дельты PROFILO этого поворота, секунды |
| `ENTROPY` | `ENTROPY <h0> <h1> …` | энтропия маршрутизации на каждом разреженном уровне хода, бит |
| `GPUS` | `GPUS <n> (<used_gb> <total_gb> <experts>)×n` | VRAM для каждого устройства + количество резидентных экспертов (сборки CUDA) |
| `TOPK` | `TOPK <id> 5 (<logprob> <hextext>)×5` | текст токена закодирован в шестнадцатеричном формате, поэтому линия остается линейной |
| `REPIN` | `REPIN <layer> <eid> <old_tier> <gpu>` | одна строка на замену горячего хранилища (режим `REPIN=n`) |

Вся телеметрия носит рекомендательный характер: серверы отображают то, что им известно, и пропускают остальное.

<a id="http-surface-openai_serverpy"></a>
## Поверхность HTTP (`openai_server.py`)

- `POST /v1/chat/completions` — OpenAI-совместимый; потоковые ответы выдают один дополнительный
  Рамка SSE `data: {"colibri": {stats, perf, topk, entropy, gpus, repin}}` сразу
  до `data: [DONE]`; непотоковые ответы присоединяют тот же объект, что и
  Поле `"colibri"`.
- `GET /experts` — последнее состояние `EMAP`/`HITS`: `{строки, столбцы, карта, попадания, последовательность,
  графический процессор, энтропия, репин}`.
- `GET /*` — статический хостинг `web/dist` (резервный SPA, безопасный при обходе пути), плюс
  `experts.json`, если он там опубликован (измеренный экспертный атлас, №175/#218).

<a id="legacy-protocol-run_serve-coli-chat"></a>
## Устаревший протокол (`run_serve`, `coli chat`)

Интерактивные линии — это подсказки; контрольные кадры: `\x02RESET` (очистить историю),
`\x02MORE` (продолжить сокращенный NGEN ответ) и
`\x02PROMPT <bytes> <max_tokens> <temperature> <top_p> [kv_slot]\n<prompt>\n`
(режим API предварительного мультиплексирования). Ответы представляют собой необработанный текст, заканчивающийся `\x01\x01END\x01\x01`.
плюс линия `STAT`. Новые интеграции должны использовать протокол мультиплексирования.

Подсказки, выходящие за рамки контекста, отклоняются и никогда не усекаются автоматически (#2097): движок
выдает пустой ответ, строку `STAT` с седьмым токеном `CONTEXT_EXCEEDED`,
и строка stderr, указывающая причину (слишком длинный запрос для контекста,
история разговоров, которая больше не помещается, или текст, обрезанный рендером размером 64 КБ.
буфер). Причина располагается на линии `STAT` как восьмой токен (`PROMPT_TOO_LONG`,
`HISTORY_FULL` или `RENDER_CLIPPED`), чтобы `coli chat` можно было напечатать его с помощью
правильная подсказка вместо пустого ответа: `:reset` очищает всю историю,
более короткая подсказка (или более крупная `CTX`) соответствует слишком длинному повороту. Поднимите `CTX` или
сократить подсказку; в чате `\x02RESET` очищает всю историю.
