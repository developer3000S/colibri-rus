# ABI среды выполнения на границе модели

`c/edge_runtime.h` - это нейтральная к движку локальная граница C Colibri для двух
концы маршрута распределенного вывода:

```text
text -> tokenizer -> embedding -> one or more Segment engines -> final head
```

Это не сетевой протокол. Colibri владеет токенизацией, математическими границами модели,
форматы и ядра; потребитель, такой как Лумабри, владеет открытиями, транспортом,
размещение, аренда и жизненный цикл сеанса. Вместе с
[`segment_runtime.h`](../../c/segment_runtime.h), это позволяет запустить процесс обмена сообщениями
реальная модель без локальной загрузки каждого слоя трансформатора.

ABI является аддитивным. Обычные Colibri интерфейсы командной строки не связывают и не регистрируют Edge.
адаптеры и сохранить существующие пути инициализации и вывода.

Внешние потребители могут создать полную базовую среду выполнения CPU с помощью
`make -C c segment-edge-library`. В результате
`c/build/segment/libcolibri_segment_edge.a` содержит как общедоступные среды выполнения, так и
все семь встроенных адаптеров. Потребители связывают его со своими объектами и называют
функции явной регистрации ниже; обычные Colibri исполняемые файлы делают
не связывать этот архив.

<a id="lifecycle-and-compatibility"></a>
## Жизненный цикл и совместимость

1. Явно зарегистрируйте необходимые адаптеры во время инициализации процесса.
   Конструкторы времени компоновки отсутствуют, в том числе в Windows.
2. Откройте одну границу модели с помощью `coli_edge_engine_open`.
3. Прочитайте его возможности и потребуйте точного совпадения с маршрутизируемым Сегментом.
   цепочка для `state_schema`, `numeric_class`, типа состояния и ширины состояния.
4. Токенизировать и внедрить промпт, пропустить его через всю цепочку сегментов,
   затем вызовите `coli_edge_select` в последней строке.
5. Для декодирования вставьте выбранный токен и повторите действия в следующей позиции.
6. Закройте механизм Edge после завершения сеансов.

Вызывающий объект инициализирует `struct_size` каждой публичной структуры. Возможность
запрашивает нулевое полное распределение вызывающего объекта перед копированием полей, известных
среда выполнения, поэтому более старая среда выполнения не может покинуть поля будущих расширений
неинициализированный.

Версия 1 намеренно использует детерминированный жадный выбор. Выборка – это
будущая аддитивная операция; он не эмулируется за пределами Colibri. Регистрация
должен завершиться перед одновременным поиском. В настоящее время потребитель должен разместить один
активная модель для каждого процесса обмена сообщениями, поскольку некоторая существующая конфигурация механизма
глобальный процесс; Производственный токенизатор Qwen делает это ограничение явным.
и отвергает второй работающий движок Qwen Edge.

<a id="real-adapters"></a>
## Реальные адаптеры

`c/edge_adapters.h` предоставляет явные функции регистрации для каждого текущего
Colibri семейство моделей:

| Адаптер | Пограничное государство | Резиденция Края |
| --- | --- | --- |
| ГЛМ-5.2 | скрытое состояние | токенизатор, встраивание, окончательная норма и голова |
| намек | скрытое состояние | токенизатор, необязательная встраиваемая норма, окончательная норма и заголовок |
| Kimi K3 | скрыт плюс все блоки AttnRes | токенизатор, финальные преобразования и голова; встраивание потока строк по требованию |
| OLMoE | скрытое состояние | токенизатор, встраивание, окончательная норма и голова |
| Квен3.6 | скрытое состояние | токенизатор, встраивание, окончательная норма и голова |
| Qwen3.8-Flash-Следующий | четырехпоточное гиперсостояние | токенизатор, встроенное в BF16, окончательный гипермикшер и встроенная голова BF16 |
| ДипСик V4 | расширенное состояние mHC | токенизатор и небольшие финальные тензоры mHC; BF16 встраивает поток строк и верхних плиток по требованию |

В настоящее время каждый адаптер объявляет только CPU. Будут добавлены флаги-акселераторы
только тогда, когда этот адаптер фактически выполняет свои операции Edge над совпадающим
Colibri бэкэнд. `resident_bytes` сообщает о тензорах модели, принадлежащих адаптеру, иможет быть ограничено `memory_limit_bytes`; файлы моделей и метаданные токенизатора
остаются дополнительные сопоставленные/индексированные ресурсы.

<a id="api-contract"></a>
## API-контракт

Токенизация и детокенизация поддерживают этап определения размера, передавая нулевой вывод с помощью
нулевая мощность. `coli_edge_embed` принимает ровно один идентификатор токена в каждой строке и выдает
`rows * state_width` значений в объявленном типе данных. `coli_edge_select`
применяет точное окончательное преобразование модели и выходной заголовок к каждой входной строке,
возвращая один жадный токен и необязательный балл в каждой строке. Edge ABI v2 также
отображает `coli_edge_logits`, который возвращает полный словарь по строкам
logits после того же преобразования, специфичного для модели. Colibri поэтому остается
владелец математических моделей, в то время как обслуживающий абонент может применять температуру, топ-п и
своя собственная воспроизводимая политика ГСЧ без дублирования какой-либо из шести головок.
`argmax(logits)` является ограниченным по сравнению с `coli_edge_select` для каждой семьи.

Среда выполнения проверяет размеры структуры, геометрию активации, пределы партии,
Выходные мощности и отмена перед входом в адаптер. Модельные адаптеры
также проверяйте идентификаторы токенов и тензоры границ контрольных точек. Оперативное и
ошибки совместимости возвращаются вызывающей стороне; сетевой уровень решает
следует ли повторить попытку, перенести или вернуться локально. Обнаружение контрольной точки все еще использует
общие аварийно-замкнутые предохранительные тензоры/загрузчики конфигурации движков: неверный или
каталог враждебной модели является фатальной ошибкой развертывания процесса, как и для
автономные механизмы, а не исправимую ошибку запроса.

<a id="all-family-release-gate"></a>
## Ворота для всей семьи

`make -C c edge-adapters` проверяет, что все семь реальных адаптеров сосуществуют в одном
время выполнения. `edge-adapters-real` — более сильные ворота: они загружаются для каждой семьи.
настоящий адаптер Edge и полный диапазон реальных сегментов, текст туда и обратно, встраивание
независимая подсказка оракула, выполняет предварительное заполнение плюс декодирование и сравнивает три
жадные токены с этим оракулом. Также требуется, чтобы сгенерированные токены были
поддается детокенизации и требует точной идентификации возможностей Edge/Segment.
Для каждого семейства шлюз дополнительно вычисляет полные логиты для первого
декодировать строку и требует, чтобы их argmax был равен уже проверенному оракулом
жадный токен.

Создайте существующие крошечные контрольные точки из `c/` (это тестовые данные и
не совершено):

```sh
python3 tools/make_glm_oracle.py
python3 tools/make_edge_tiny_tokenizer.py glm_tiny --vocab-size 256

python3 tools/make_tiny_inkling.py tiny_inkling
python3 tools/make_edge_tiny_tokenizer.py tiny_inkling --vocab-size 256

python3 tools/make_kimi_k3_tiny.py --output kimi_k3_tiny --force
python3 tools/make_edge_tiny_tokenizer.py kimi_k3_tiny --vocab-size 320

python3 tools/make_olmoe_tiny.py --output olmoe_tiny_src --force
python3 tools/make_edge_tiny_tokenizer.py olmoe_tiny_src --vocab-size 128
python3 tools/convert_olmoe_merged.py --model olmoe_tiny_src \
  --out olmoe_tiny_merged --min-free-gb 0

python3 tools/make_qwen36_tiny.py --out qwen36_edge_src \
  --emit-ref qwen36_edge_src/ref_qwen36.json --ref-mode full --max-new 8
python3 tools/make_edge_tiny_tokenizer.py qwen36_edge_src --vocab-size 320
python3 tools/convert_qwen36.py --model qwen36_edge_src \
  --out qwen36_edge_i8 --ebits 8 --no-readme

python3 tools/make_qwen38_tiny.py --out qwen38_tiny
python3 tools/make_edge_tiny_tokenizer.py qwen38_tiny --vocab-size 64

python3 tools/make_deepseek_v4_tiny.py --output deepseek_v4_edge_tiny --force
python3 tools/make_edge_tiny_tokenizer.py deepseek_v4_edge_tiny --vocab-size 128
```

Генератор Инклинга требует `c/tools/oracle-requirements.txt`. Затем запустите
одинарные общесемейные ворота:

```sh
make -C c edge-adapters-real \
  GLM_EDGE_MODEL=glm_tiny GLM_EDGE_REF=ref_glm.json \
  INKLING_EDGE_MODEL=tiny_inkling \
  INKLING_EDGE_REF=tiny_inkling/ref_inkling.json \
  KIMI_EDGE_MODEL=kimi_k3_tiny KIMI_EDGE_REF=kimi_k3_tiny/ref.json \
  OLMOE_EDGE_MODEL=olmoe_tiny_merged \
  OLMOE_EDGE_REF=olmoe_tiny_src/ref_olmoe.json \
  QWEN_EDGE_MODEL=qwen36_edge_i8 \
  QWEN_EDGE_REF=qwen36_edge_src/ref_qwen36.json \
  QWEN38_EDGE_MODEL=qwen38_tiny \
  QWEN38_EDGE_REF=qwen38_tiny/ref.json \
  DEEPSEEK_EDGE_MODEL=deepseek_v4_edge_tiny \
  DEEPSEEK_EDGE_REF=deepseek_v4_edge_tiny/ref.json
```

Помощник токенизатора фикстуры заполняет только токенизатор, намеренно пропущенный
только математические генераторы. Пункты пропуска всегда используют свою продукцию
токенизатор. Семья не считается обеспеченной с момента регистрации или
только синтетический адаптер: эти ворота оракула должны пройти для всех существующих семейств.
