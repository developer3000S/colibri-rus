# Серверная часть XDNA (Windows, AMD Ryzen AI NPU)

colibrì включает в себя **экспериментальный** бэкэнд, на котором работает GLM.
операции на процессоре AMD XDNA2 NPU с использованием **вычислительного пути BF16 пониженной точности**.
По умолчанию он отключен, никогда не выбирается автоматически, и выходные данные модели могут
отличаться от обычного пути.

```bash
coli run --xdna "your prompt"
```

Без `--xdna` ничего не меняется: не загружается помощник, не открывается устройство и
движок дает именно те результаты, которые он дает сегодня. Установка
Дополнительный пакет сам по себе ничего не включает.

`--xdna` работает, устанавливая `COLI_XDNA=1` для движка, и движок считывает это
переменную напрямую — поэтому, если вы экспортируете ее самостоятельно, это будет иметь тот же эффект, с или
без флага. Это единственный другой путь внутрь.

<a id="what-runs-on-the-npu"></a>
## Что работает на NPU

Только **прогноз МООС по открытию/повышению уровня** для GLM
(`K=6144, N=2048`, fmt=4 сгруппировано int4, размер группы 64), и только в последовательности
длины, охватываемые квалифицированными артефактами:

| строк за вызов | работает |
|---|---|
| 1 – 64 | НПУ, артефакт М64 |
| 65 – 256 | НПУ, артефакт М256 |
| более 256 | нормальный путь |

Все остальное — проекция вниз, разгромленные эксперты, внимание и все остальное.
модель — использует обычный путь. Любая операция, не поддерживаемая полосой, и любые
сбой во время выполнения, возвращается к точным вычислениям, которые выполняет движок
без этого бэкэнда.

<a id="precision"></a>
## Точность

Путь NPU преобразует активации и веса в BF16 и накапливает их в F32.
Это **не** та же арифметика, что и обычный путь, и не утверждается, что она
быть эквивалентным:

- оценки каждого варианта в небольшом внутреннем тесте менялись при каждой операции
  НПУ обработано;
- в отдельном эксперименте с автономной генерацией выдано 5 из 8 подсказок
  **другой текст**.

Имеет ли это значение для вашего использования — решать вам. Режим
существует, поэтому выбор очевиден.

<a id="installing-the-optional-package"></a>
## Установка дополнительного пакета

Серверной части NPU помимо исполняемого файла нужны еще две вещи: вспомогательная DLL и
квалифицированные артефакты ядра. Они поставляются как отдельная дополнительная загрузка, а не в
главный архив.

Распакуйте его в каталог colibrì, чтобы макет был таким:

```
<colibri directory>\
    colibri.exe
    coli_xdna.dll
    xdna\
        wa_F3_M64_K6144_N2048.xclbin
        wa_F3_M64_K6144_N2048_insts.bin
        wa_F3_M256_K6144_N2048.xclbin
        wa_F3_M256_K6144_N2048_insts.bin
```

Оба местоположения разрешаются **относительно исполняемого файла** по абсолютному пути.
`PATH` и рабочий каталог не ищется, поэтому пакет должен находиться в
это одно место. Каждый артефакт проверяется по хешу, встроенному в двоичный файл.
прежде чем он будет использован.

<a id="what-the-optional-package-needs-installed"></a>
## Что необходимо установить дополнительному пакету

Коляска маленькая, потому что в нее входят только помощник и ядра. Два
вещи уже должны быть на машине до `coli_xdna.dll` для загрузки:

- **Среда выполнения AMD XRT** (`xrt_coreutil.dll`) из установки AMD Ryzen AI/XRT.
- **Распространяемый пакет Microsoft Visual C++** (x64). Помощник построен на MSVC.
  — именно так он достигает интерфейса C++ XRT — поэтому он импортирует `MSVCP140.dll`,
  `VCRUNTIME140.dll` и `VCRUNTIME140_1.dll`.

Ни то, ни другое не входит в комплект. Если что-то отсутствует, помощник просто не загрузится, и
`--xdna` сообщает об этом и продолжает свой обычный путь:

```
[XDNA] requested, and the artifact package is valid, but the XDNA helper
       (coli_xdna.dll) is not usable beside the executable: continuing on the
       normal path
```

**Обычному хосту colibrì не требуется ни то, ни другое.** Он импортирует только Windows.
системные библиотеки, со встроенными возможностями NPU или без них — внешние
зависимости относятся только к дополнительному пакету.

Также требуется: Windows и NPU класса XDNA2.

<a id="when-something-is-missing"></a>
## Когда чего-то не хватает`--xdna` всегда сообщает вам, что произошло, и всегда продолжает работать в обычном режиме.
путь:

```
[XDNA] requested, but this build has no XDNA support: continuing on the normal path
[XDNA] requested, but the XDNA package was not found at <dir>\xdna: continuing on the normal path
[XDNA] requested, but the XDNA package is incomplete (missing <file>) in <dir>\xdna: ...
[XDNA] requested, but an XDNA artifact does not match its expected hash (<file>):
       refusing to use it, continuing on the normal path
[XDNA] requested, and the artifact package is valid, but the XDNA helper
       (coli_xdna.dll) is not usable beside the executable: ...
```

Артефакт, чьи байты не соответствуют ожидаемому хешу, отклоняется, даже если
вы запросили NPU — байты, которые не являются квалифицированными байтами, не являются
квалифицированное ядро.

Когда все будет на месте, вы получите уведомление об активации один раз:

```
[XDNA] experimental: qualified GLM shared expert operations will use the
[XDNA] native NPU with a reduced-precision BF16 compute path. Model output
[XDNA] may differ from the normal path, and generated text has been observed
[XDNA] to diverge. Operations this lane does not support continue to use the
[XDNA] normal path.
```

Все это поступает в стандартный поток ошибок и никогда не смешивается с машиночитаемым выводом.


<a id="producing-the-optional-package-maintainers"></a>
## Создание дополнительного пакета (сопроводителей)

CI не может собрать этот пакет. Помощнику нужен XRT SDK и артефакты.
нужна цепочка инструментов AIE, а у разработчиков релизов нет ни того, ни другого — вот почему
Задание Windows создает хост с поддержкой XDNA и на этом останавливается. Коляска производится
на соответствующей машине и прикрепленной к той же версии.

Все, что ниже, принадлежит `c/tools/build_xdna_package.py`. Он читает
ожидаемые имена и хэши артефактов из `c/backend_xdna.c`, поэтому пакет может
никогда не отклоняйтесь от того, что движок принимает во время работы.

```bash
python tools/build_xdna_package.py \
    --helper   <path to the built coli_xdna.dll> \
    --artifacts <directory holding the four qualified artifacts> \
    --out      dist/xdna-pkg \
    --release --dist dist
```

Это проверяет каждый ввод на соответствие скомпилированному реестру *перед* записью.
что угодно, затем создает три файла с именами из `version.py`:

```
colibri-<tag>-windows-x86_64-xdna.zip            the sidecar
colibri-<tag>-windows-x86_64-xdna.manifest.txt   sizes, hashes, roles, version
colibri-<tag>-windows-x86_64-xdna.sha256         sha256sum format
```

Имя сохраняет основу основного архива и добавляет `-xdna`, поэтому оно находится рядом.
`colibri-<tag>-windows-x86_64.zip`, соответствует собственному заданию выпуска
`sha256sum colibri-*`, и его нельзя спутать с основной загрузкой.

Архив воспроизводим: тот же помощник и те же квалифицированные артефакты.
производят одни и те же байты и, следовательно, один и тот же sha256, где бы они ни находились.
откуда и какое время содержат эти файлы. Если вы восстановите коляску и
контрольная сумма сместилась, что-то в *контенте* изменилось — это сигнал, а не шум.

Перед публикацией повторно проверьте созданные ресурсы:

```bash
python tools/build_xdna_package.py --verify-release dist/colibri-<tag>-windows-x86_64-xdna.zip
```

Это отказывается проходить, если архив не соответствует его манифесту, если манифест
называет версию выпуска, отличную от версии файла, или если какой-либо дайджест артефакта
не согласен с составленным реестром. Прикрепляйте только после того, как он напечатает `release
assets OK` — the command to do so is printed by `--release` и использует тот же
`gh release upload ... --clobber` используется сам рабочий процесс выпуска.

**Никогда не объединяйте** `xrt_core.dll`, `xrt_coreutil.dll`, распространяемый MSVC,
Инструментальная цепочка AIE или любой заголовок SDK. Их устанавливает пользователь; коляска это
только собственный помощник и артефакты colibrì.

Чтобы убедиться, что обычная загрузка не затронута, установите основной архив на его
работает нормально: ни один помощник не загружается, ни одно устройство не открывается, и ничего
об изменениях пути по умолчанию.

<a id="what-this-backend-does-not-do"></a>
## Чего этот бэкэнд не делает

- Это не возможно при наличии оборудования, помощника или пакета.
- Он не выбирает между NPU и обычным путем по скорости или стоимости.
- Здесь не делается никаких заявлений о скорости.
- Это не распространяется на другие модели или другие операции.
