# Мистраль-Большой-4 (`c/colibri.c`)

[Mistral-Large-4-1T-A52B](https://huggingface.co/mistralai/Mistral-Large-4-1T-A52B): параметры 1T,
52B активных, 72 слоя, скрытых 6144, 64 головы, 128 перенаправленных экспертов (по 4 на токен) и один общий,
первый слой плотный, словарь 204800. Его текстовая модель представляет собой внимание DSA GLM-5.2 с шестью
изменения, поэтому он работает на движке GLM-5.2 (`colibri.c`, семейство `glm` в `coli`).

```
./coli import ~/models/Mistral-Large-4-1T-A52B-UD-IQ1_S-00001-of-00006.gguf   # first part of a split model
./coli chat --model ~/models/Mistral-Large-4-1T-A52B-UD-IQ1_S.colibri
```

<a id="what-differs-from-glm-52"></a>
## Чем отличается от GLM-5.2

- **Нет запроса LoRA.** Запрос поступает прямо из входных данных слоя (`q_proj`, `attn_q` GGUF).
- **Слои NoPE.** Каждый четвертый слой (`no_rope_layers` 0, `rope_pattern` ложь GGUF) не имеет
  поворотная часть: все 128 диммеров головки опроса не вращаются, а скрытая часть не имеет поворотного ключа.
- **Общий KV.** Слои 39, 43, ..., 71 читают скрытые данные слоя 35 (`kv_source_layers`, GGUF
  `kv_source_map`) и не имеют своих `kv_a`; их `kv_b` — их собственные. Движок копирует
  строки источника в кеш читателя по мере их записи.
- **SSMax.** Запрос каждой головы умножается на `s * log(position + 1) + b`, свои собственные `s` и `b`, в
  внимание и в индексаторе.
- **Индексатор.** `q = wq_b(LayerNorm(x))` с SSMax, `k = LayerNorm(wk(x))`, оба вращаются
  их первые 64 димма на слоях RoPE; баллы `relu(q . k / sqrt(128))`, взвешенные по
  `weights_proj(x) / sqrt(32)`, сохранены 2048 верхних ключей. «Общий» слой считывает выборку
  последний полный слой перед ним.
- **RoPE и остальное.** Чередование пар; Частоты ЯРН (коэффициент 2048 на 512, внимание
  коэффициент 1), разделенный на изученный коэффициент на пару (`rope_freqs` GGUF равен `exp(-alpha)`
  контрольно-пропускной пункт `lerope.alpha`); маршрутизатор softmax, перенормированный по своим верхним 4; логиты ограничены
  30 (`30 * tanh(z / 30)`).

Токенизатор — Tekken (`tok.h`): шаблон o200k без английских сокращений и цифр.
группами по три человека справа. В выпуске `tokenizer.json` он разбивает 3017 тестовых строк.
как это делают трансформаторы (`tests/test_tok_tekken.c` содержит крошечное приспособление).

Шлюз записывает чат, как это делает `chat_template.jinja` релиза, байт за байтом.
(`tests/test_mistral_large4_chat.py`, `COLI_ML4_TEMPLATE`, указывая на шаблон, запускает эту проверку):
`[MODEL_SETTINGS]` с рассуждением, `[INST]` ходами, инструментами и их результатами. Модель
рассуждения возвращаются как `[THINK]...[/THINK]`, что шлюз выдает как `reasoning_content`, и
он вызывает как `[TOOL_CALLS]name[ARGS]{json}`, что дает как `tool_calls`.

## Из версии FP8

`tools/convert_fp8_to_int4.py` читает собственный выпуск Mistral: `consolidated-*.safetensors` в
Имена Мистраля (`layers.N.attention.wq`, `experts.E.w1/w2/w3`, `shared_experts`, `gate`,
`ssmax_scaling`, `lerope.alpha`), FP8 с `qscale_weight` на блок 128 x 128.

```
python3 tools/convert_fp8_to_int4.py --repo mistralai/Mistral-Large-4-1T-A52B --outdir ~/models/mistral-large4-colibri
```

Он скачивает шард, конвертирует его и удаляет, поэтому релиз (1060 ГБ) никогда не сидит на диске
целый. По умолчанию используется int4 с масштабом 64 для каждой матрицы, int8 для вложений и
голова (`--ebits`, `--xbits`, `--io-bits` измените их). Проверено на собственных байтах релиза по сравнению с
GGUF Q8_0: `qscale_weight` умножается (деление отключено на 1e7), `w1` — это ворота и `w3` — вверх.
Конвертер пишет ровное `config.json` движка (выпуск сохраняется как `config.hf.json`).

В релизе также присутствует башня видений (`vision_encoder.*`, `vision_language_adapter.*`,
`patch_merger.*`, `pre_mm_projector_norm.*`, BF16): преобразователь сохраняет всё как есть и записывает
контейнера `mmproj.gguf` и `preprocessor_config.json`, которые обслуживают режим, а шлюз читается как
Связанный с папкой GGUF файл mmproj. Созданный таким образом из релиза, файл является репозиторием GGUF.
`mmproj-BF16.gguf` тензор за тензором (276 тензоров, те же байты, проверено на реальных файлах). Аконтейнер, преобразованный до этого, или любая другая папка, получает его только из выпуска (только
извлекаются 3,4 ГБ башни):

```
python3 tools/ml4_mmproj.py --release mistralai/Mistral-Large-4-1T-A52B --out ~/models/mistral-large4-colibri
```

Контейнер тоже работает на CUDA (эксперты и плотные матрицы на карте, `CUDA_DENSE=1`).
Контейнер int4 крошечной модели предоставляет одни и те же токены на CPU, CUDA и Vulkan, логиты внутри
около 1% друг от друга.
