#GLiNER2.5-Определитесь с colibri

[GLiNER2.5-Decide](https://huggingface.co/fastino/GLiNER2.5-Decide), автор
fastino (Apache-2.0) — классификатор операционных решений: намерение,
маршрутизация, тональность, срочность, модерация, вопросы да/нет по отрывку,
порядковые баллы. Это контрольная точка GLiNER2, большой кодер DeBERTa-v3 с
Головы GLiNER2, и он никогда не генерирует текст.

`c/gliner_decide` запускает его с официального чекпоинта без конвертации,
и `coli serve` выставляет его на `POST /v1/systemone`, тот же запрос и
отвечайте как Jev API TypeSafe и как любая другая модель colibri
([systemone.md](systemone.md#decision-engines)).

## Загрузите и запустите

Контрольная точка — корень репозитория (1,9 ГБ, F32):

```sh
hf download fastino/GLiNER2.5-Decide model.safetensors config.json \
   "encoder_config/*" tokenizer.json tokenizer_config.json special_tokens_map.json \
   --local-dir ~/Models/GLiNER2.5-Decide
make -C c gliner_decide
./c/coli serve --model ~/Models/GLiNER2.5-Decide
```

`coli` распознает контрольную точку по своему `config.json` (`model_type`
`extractor`, GLiNER2 или `gliner2`, как указано в конфигурации репозитория, поскольку его
форма трансформаторов, одинаковые веса) и `encoder_config/config.json` энкодера; тот
ключи реестра это `gliner2_span_deberta-v2`. `coli info` показывает кодировщик и
бюджет токена, `coli plan` ОЗУ, `coli doctor` чего не хватает.

```sh
curl -s localhost:8000/v1/systemone -H 'Content-Type: application/json' -d '{
  "model": "jev-latest",
```

## От Системы Один к задаче модели

GLiNER2 не имеет понятия выбора, оценки или ноля: он классифицирует текст по
именованные задачи, каждая со своей меткой. Механизм превращает запрос System One в
звонок, который делает карточка-модель, `classify_text(state, tasks)`, одно задание на каждого
вопрос в указанном порядке:

| Система Один | Задача GLiNER2 |
|---|---|
| идентификатор вопроса | имя задачи (`department`, `urgency`) |
| `instructions` | задача `prompt` (`department: Which department should handle this?`) |
| `choice` критерии | этикетки по порядку; непустое описание становится описанием метки |
| `score` критерии | метки `"0"` .. `"n-1"`, то, как на карточке модели записан порядковый номер; текст каждого уровня становится его описанием |
| `noul` | метки `"yes"`, затем `"no"`, порядок каждого примера «да/нет» на карточке модели; `criteria.true` / `criteria.false` опиши их |

Каждая задача является однокомпонентной, поэтому ее вероятности представляют собой softmax по ее значению.
метки, что `classify_text` возвращает для задачи с одной меткой.
из них следует ответ, как и на каждом движке: `choice` — argmax, `score`
ожидаемый уровень, `noul` вероятность `yes`.

Два последствия чтения запроса как одного вызова:

- **Все вопросы имеют одну последовательность.** Кодировщик считывает каждый вопрос.
  схема и состояние вместе, поэтому вероятности вопроса зависят от
  другие вопросы того же запроса, как и в пакете, когда один
  звонок оценивает несколько задач (сортировка электронной почты по типовой карточке). Один запрос
  один проход вперед, независимо от количества вопросов.
- **Недостающие инструкции заполняются шлюзом** текстом
  Путь к языковой модели запрашивает (`Which of the following applies?`,
  `Rate this on the scale below.`, `Is this true?`). Для GLiNER2 этот текст
  становится подсказкой задачи. Измерено на одиннадцати примерах однозадачных
  карточка модели, задается без подсказки и с картой по умолчанию (`Is this true?`
  для меток «да/нет»: `Rate this on the scale below.` для 0–5 и 0–10.
  весы, `Which of the following applies?` для остальных), подсказка по умолчанию
  не изменил решения и переместил максимальную вероятность менее чем на 0,001 до
  0,12 (refund_request 0,997 -> 0,969, Seat_change 0,501 -> 0,622). Отправить
  `instructions`, когда они у вас есть.

## Что вычисляет движокКаждый шаг соответствует пакету `gliner2` (2.0.0) и преобразователям.
Код DeBERTa-v2, который он запускает, является ссылкой:

| шаг | ссылка | в `c/gliner_decide.c` |
|---|---|---|
| текст | `processor._collate_batch` | `.` добавляется, если штат не заканчивается на `.`, `!` или `?`; пустое состояние — `.` |
| слова | `processing/word_splitter.WhitespaceTokenSplitter` | Регулярное выражение Python (URL-адреса, электронные письма, @handles, `\w+(?:[-_]\w+)*`, `\S`) с собственными Python `\w`, `\s` и `re.IGNORECASE`, каждое слово в нижнем регистре с `str.lower()` (последняя сигма и заглавная точка с точками, которые я включил); таблицы взяты из Python автором `tools/gen_gliner_unicode.py` |
| схема | `Schema.classification`, `processor._transform_schema` | за задачу `( [P] name[: prompt][ [DESCRIPTION] label: text ...]( [L] label ... ) )`, задачи, объединенные `[SEP_STRUCT]`, затем `[SEP_TEXT]` и слова |
| токены | `processor._format_input_with_mapping` | каждый элемент выше токенизирован отдельно, без `[CLS]` или `[SEP]`; классификатор считывает первый токен каждого `[L]` |
| токенизатор | `tokenizer.json` (DebertaV2TokenizerFast) | добавлены токены, выделенные из необработанного текста, `Replace(\s{2,}\|[\n\r\t] -> " ")`, NFC, правая полоса, `[UNK]`, сопоставленные после нормализации, Metaspace (всегда добавлять в начале, разделить), Unigram (сегментация с лучшими оценками, неизвестные символы с минимальным счетом - 10, соседние неизвестные символы объединены в один `[UNK]`) |
| кодер | `DebertaV2Model` | встраивание слов и LayerNorm (без абсолютных позиций); 24 постнормальных слоя распутанного внимания: `(q.k + q.pos_k[r] + k.pos_q[r]) / sqrt(3 * 64)` с `r` относительным положением в сегментах журнала (256 сегментов, максимум 512, привязанных к таблице из 512 строк), `pos_q` и `pos_k` относительным встраиванием LayerNorm через собственный запрос слоя и ключевые проекции; ГЕЛУ ФФН |
| голова | `runtime._extract_classification_result` | классификатор (Линейное письмо 1024 -> 2048, ReLU, Линейное письмо 2048 -> 1) на каждом `[L]`, температуре 1, softmax над метками задач |

Заголовки диапазона, подсчета и связи (`span_rep`, `count_pred`,
`count_embed`) служат для добычи и не загружаются. Относительные вложения
одинаковы для каждого запроса, поэтому их проекции вычисляются один раз
нагрузка. Веса сохраняются в f32 в том виде, в каком они были выпущены.

Измерено на ноутбуке i7-1355U (10 ядер, 12 потоков), 6 потоков у обоих
сторон на машине, используемой совместно с другими рабочими местами: средняя нагрузка оставалась в пределах
10 и 13 во время прогонов ниже, поэтому абсолютные числа меняются от прогона к прогону.
Движок и пакет запускались по очереди, запрос за запросом, так что оба видели
та же нагрузка (в среднем 5 каждый):

| запрос | токены | `coli serve`, у клиента | какой движок | `gliner2` пакет (фонарик, CPU, f32) |
|---|---|---|---|---|
| один вопрос (карточка модели, спам или нет) | 37 | 294 мс | 290 мс | 718 мс |
| запрос README, 3 вопроса | 118 | 897 мс | 888 мс | 1217 мс |
| десять вопросов в одном билете | 286 | 1955 мс | 1950 мс | 2231 мс |
| контракт, 3 вопроса | 965 | 8401 мс | 8397 мс | 9457 мс |

Доля шлюза составляет от 4 до 10 мс. Более 39 запросов сравнения

Более длинные последовательности стоят дороже, чем пропорционально, а внимание растет с увеличением

|---|---|---|
| `COLI_GLINER_MAX_LEN` | 4096 | токены одной последовательности, которой становится запрос: сначала вопросы, затем столько целых слов состояния, сколько поместится |

<a id="knobs"></a>
## Ограничения

- **Английский.** Модель карты измеряет этот контрольный пункт на английском языке; фастино
  указывает на GLiNER2.5-multi-Decide для других языков, которые есть в этом движке
  не обкатывался.
- **Калибровка не поставляется вместе с контрольной точкой.** Вероятности указаны
  softmax классификатора при температуре 1, поскольку пакет их вычисляет;
  `temperature` в рамке РЕШЕНИЕ — это `null`.
- **Только один вопрос.** В System One нет вопросов с несколькими критериями, поэтомурежим `multi_label` пакета (сигмовидная черта на метку и порог) не поддерживается.
  достижимый; Вместо этого запрашивайте один ноул за этикетку, как это сделано в приведенном выше сравнении.
- **Длинные состояния.** По умолчанию пакет читает весь текст; движок
  останавливается на уровне `COLI_GLINER_MAX_LEN` токенов, так что один запрос не может принять
  машина, а `state_dropped` в кадре РЕШЕНИЕ говорит, сколько состояний
  токены были оставлены. Ниже предела оба читают одни и те же токены.
  стоимость растет пропорционально квадрату длины (см. Скорость).
- **Порядок меток `noul`.** Движок запрашивает `yes` перед `no`; порядок
  немного перемещает вероятности (пример передачи карточки модели:
  p(да) 0,325 сначала спросили «да», 0,297 сначала спросили «нет»), никогда не принималось решение о
  примеры измерены.
- **Идентификаторы вопросов, дополняющие друг друга.** Пакет находит ответ на задачу.
  по префиксу текста схемы, то есть с двумя идентификаторами вопросов, например `risk`
  (с инструкциями `score it`) и `risk: score`, `classify_text` возвращает
  только один из них (проверено на крохотном приспособлении). Движок отвечает на все
  вопрос по позиции.
- **Другие контрольные точки GLiNER2.** Реестр принимает любой диапазон GLiNER2.
  контрольная точка с кодером DeBERTa-v2/v3, а кодировщик 24 x 1024 называется
  GLiNER2.5-Решайте. Только `fastino/GLiNER2.5-Decide` сравнивали с
  пакет; от пограничной архитектуры отказываются.
