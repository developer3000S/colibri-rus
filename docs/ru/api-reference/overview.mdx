`coli serve` поддерживает загрузку одного процесса модели и предоставляет конечные точки HTTP, совместимые с OpenAI и Anthropic, через шлюз стандартной библиотеки Python.

<a id="start-the-server"></a>
## Запускаем сервер

```bash
COLI_MODEL=/nvme/glm52_i4 \
COLI_API_KEY=local-secret \
./coli serve --host 127.0.0.1 --port 8000 --model-id glm-5.2-colibri
```

Базовый URL-адрес по умолчанию — `http://127.0.0.1:8000`. OpenAI-совместимые клиенты обычно используют `http://127.0.0.1:8000/v1`.

<a id="authenticate"></a>
## Аутентификация

Если установлено `COLI_API_KEY`, отправьте любой из этих заголовков:

```http
Authorization: Bearer local-secret
```

```http
x-api-key: local-secret
```

<Note>
`GET /health`, `GET /experts` и `GET /profile` остаются доступными для локальных информационных панелей. Без действительной аутентификации они возвращают только общедоступные или пустые данные; аутентифицированные запросы включают планировщик, маршрутизацию или пошаговую телеметрию.
</Note>

<a id="choose-a-protocol"></a>
## Выберите протокол

<Tabs>
  <Tab title="ОпенАИ">
    Используйте `POST /v1/chat/completions` для сообщений или устаревший `POST /v1/completions` для текстовой подсказки. Оба поддерживают JSON и ответы на события, отправленные сервером.
  </Tab>
  <Tab title="антропный">
    Используйте `POST /v1/messages`. Шлюз преобразует поддерживаемые поля сообщений, мышления и использования инструментов в собственный протокол подсказок активного механизма.
  </Tab>
</Tabs>

<a id="concurrency-and-backpressure"></a>
## Параллелизм и противодавление

Один процесс механизма генерирует одну последовательность за раз. Параллельные HTTP-запросы попадают в ограниченную очередь FIFO вместо загрузки повторяющихся копий модели. Настройте его с помощью `--max-queue` и `--queue-timeout` или `COLI_MAX_QUEUE` и `COLI_QUEUE_TIMEOUT`.

Насыщенные или просроченные запросы получают HTTP `429`. Успешные ответы поколения включают `x-colibri-queue-wait-ms`.

<a id="compatibility-boundaries"></a>
## Границы совместимости

- Изображения, вероятности журналов и штрафы за токены возвращают явные ошибки, а не игнорируются.
- Звук принимается только на контрольно-пропускных пунктах Inkling с поддержкой звука.
- Вызов инструмента зависит от активного движка модели.
- `stop_sequences`, `top_k` и нетекстовые блоки антропного контента явно отклоняются.

Прочтите [полное руководство по API](/ru/api), чтобы узнать о поддержке инструментов для конкретного ядра, слотах кэша KV, примерах клиентов кодирования и ожидаемой производительности.
