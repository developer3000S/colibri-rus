# Kimi K3 — Металлическая настройка и производительность (Apple Silicon)

Измерено на **M5 Max, 128 ГБ** (унифицированная память), модель разделена на две части.
проезжает через `K3_DIRS`. Kimi K3 — самый дисковый движок в проекте, поэтому
эти результаты отделяют **вычисления** (где выигрывает графический процессор) от **декодирования
настенные часы** (которые управляются потоковой передачей Routed-Expert, а не серверной частью).

<a id="recommended-settings-m5-max-128-gb"></a>
## Рекомендуемые настройки (M5 Max, 128 ГБ)

Металл:

```
K3_METAL=1 K3_PIPE=1 K3_DIRECT=1 K3_EXPERT_GB=44 K3_LOAD_THREADS=6 OMP_NUM_THREADS=18 \
  ./kimi_k3 <model_dir> "<prompt>" --ngen N
```

CPU (металл выключен), для справки/корректности оракула:

```
K3_METAL=0 K3_PIPE=1 K3_DIRECT=1 K3_EXPERT_GB=48 K3_LOAD_THREADS=6 OMP_NUM_THREADS=18 \
  ./kimi_k3 <model_dir> "<prompt>" --ngen N
```

Стройте с помощью `make -C c kimi_k3 METAL=1`.

<a id="speed-improvement-metal-vs-cpu-matched-expert-hit-rate"></a>
## Улучшение скорости (металл против процессора, соответствующий экспертный рейтинг попаданий)

Чистая победа «яблоки к яблокам» происходит на этапах, связанных с вычислениями:

| Фаза | CPU (`K3_METAL=0`) | Металл (`K3_METAL=1`) | Ускорение |
|---|---|---|---|
| Предварительное заполнение (подсказка из 13 токенов) | 45,4 с | 27,2 с | **1,7×** |
| Внимание (`time: attn`) | 34,5 с | 14,4 с | **2,4×** |

Настенные часы декодирования привязаны к вводу/выводу (направленный поток экспертов с диска в этом кэше
размеры), поэтому он устанавливается экспертным кешем и хранилищем, а не вычислительными
Бэкэнд — декодирование Metal и CPU закрывается после сопоставления кеша.
`time: attn / moe / eload` разбивка печатается для каждого запуска, поэтому разделение
проверяемый.

<a id="tuning-findings"></a>
## Выводы по настройке

<a id="omp_num_threads-18-all-logical-cores"></a>
### `OMP_NUM_THREADS` — 18 (все логические ядра)

Размах 6→18. **18 обеспечил наилучшую пропускную способность декодирования (0,28tok/s).** Встроенный
auto-sizer (`omp_tune.h`) ограничивает команду OpenMP `perflevel0` ядрами (6 на этом
чип), что верно для компоновок P+E, но неверно здесь: второй уровень M5 Max.
работает ~0,70× на ядро — значительно выше уровня безубыточности `N_fast/(N_fast+N_slow)=0.33`
для планирования с равным разделением — поэтому включение всех 18 помогает, а не тянет.
`OMP_NUM_THREADS` переопределяет автоматический размер (он дает результат, если установлена ​​переменная env).

<a id="k3_expert_gb-4044"></a>
### `K3_EXPERT_GB` — ~40–44

Размах 8→96. **Метрики, управляемые кэшем, являются монотонными**: коэффициент попадания 4→53%, байты.
транслируются и `eload` падают по мере роста бюджета. Но `eload` падает на пол.
(~10 секунд), а прирост количества попаданий стабилизируется примерно на **44 ГБ** – сверх этого вы покупаете менее 1 % попадания.
для большей памяти. На пути CPU эквивалентное колено составляет ~48 ГБ; Металл сидит
нажмите ниже, потому что буферы, подключенные к графическому процессору, ограничивают запас.

**Потолок нехватки памяти:** при очень большом бюджете (≈96 ГБ) машина опрокидывается
в компрессор памяти macOS, и *все* замедляется в 3–5 раз, включая
фазы чистых вычислений (`attn`, `head`), которые никогда не затрагивают кэш — говорят об этом
это давление системы, а не эффект кэша. `attn` — канарейка: она остается плоской
пока не начнется давление. Сохранять общий объем (≈35 ГБ веса + кэш + KV + ОС
запас) комфортно менее ~100 ГБ на коробке емкостью 128 ГБ.

<a id="k3_load_threads-6"></a>
### `K3_LOAD_THREADS` — 6

Параллелизм хранения для устройства предварительной выборки `K3_PIPE`; 6 хорошо сбалансирован против
18-поточная вычислительная группа на пути CPU. На пути Металла (вычисления разгружены)
это, вероятно, может быть выше — перепроверьте, настроена ли настройка специально для декодирования графического процессора.

<a id="caveats-on-measurement"></a>
## Предостережения относительно измерений

- Одиночные короткие (16 токенов) прогоны шумные; тепловое состояние и фоновая нагрузка могут
  изменить тайминги вычислений в несколько раз в ходе последовательной развертки. Для
  заслуживающие доверия цифры, пройдите каждую точку 2–3 раза и потратьте **минуту**, добавьте время восстановления,
  и используйте более длинные `--ngen` (32–64), чтобы разминка/накладные расходы не доминировали.
- О размере кэша судите по монотонным сигналам (`hit`, `streamed`, `eload`), а не по
  одно время декодирования.

<a id="what-transfers-cpu-gpu"></a>
## Что переносит CPU → GPU

- **Передача:** кривая скорости попадания `K3_EXPERT_GB` (маршрутизация/кэширование осуществляется процессором и
  идентичны) и `K3_LOAD_THREADS` (привязка к месту хранения).- **Вновь откройте для себя графический процессор:** потолок давления `K3_EXPERT_GB` (проводка графического процессора опускается
  это) и `OMP_NUM_THREADS` (большая часть вычислений переносится на графический процессор, поэтому команда процессоров
  оптимальные переключения — обычно ниже).
