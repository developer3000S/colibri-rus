# Бэкэнд CUDA (Linux)

colibrì включает в себя дополнительный бэкэнд CUDA для резидентных тензоров модели. Потоковое вещание
эксперты намеренно остаются на исходном пути CPU: копирование эксперта из
NVMe к графическому процессору при каждом использовании только заменит узкое место диска на PCIe.
узкое место. Резидентные квантованные тензоры лениво загружаются один раз и используются повторно.

```bash
cd c
make cuda-test CUDA=1                  # q8/q4/q2/f32 kernel correctness
make CUDA=1
# optional dense-path experiment (hot experts are configured below)
COLI_CUDA=1 COLI_GPU=0 CUDA_DENSE=1 SNAP=/nvme/glm52_i4 ./colibri 64 4 4
```

Требования: Linux, драйвер NVIDIA и набор инструментов CUDA в разделе
`/usr/local/cuda` (переопределить с помощью `CUDA_HOME=/path/to/cuda`).
`CUDA_ARCH=native` строится для графического процессора на текущей машине. Запрос CUDA
с двоичным файлом только для CPU, недопустимым устройством или недоступной средой выполнения происходит сбой при
запуск вместо того, чтобы молча отступать. Для Windows см.
[windows.md](windows.md) (путь к DLL среды выполнения).

Этот путь отключен в обычных сборках. DietGPU сначала должен быть создан как общий

## Уровень эксперта по маршрутизации движков на CUDA (`cu_tier`)

Уровень маршрутизированного эксперта, общий для движков Vulkan (`c/vk_tier.c`, [vulkan.md](vulkan.md#the-routed-expert-tier-vk_tierc)) также работает на устройстве CUDA: `c/cu_tier.c` снова компилирует тот же файл через серверную часть CUDA (`c/cu_xb.cu`, через таблицу в `c/cu_tier_ops.h`), поэтому история, теплый старт, рекламные акции, пул хостов и гибрид шаги соответствуют уровню Vulkanа, а его линии читают `[CUDA] tier <engine>`. Для этого требуются те же настройки `COLI_VK_TIER*`.

- **Форматы:** colibri (int8 по строке или по группе, пары int4, int3-g64, MXFP4, FP8, bf16, f32) и типы блоков GGUF, имеющиеся в файле, через те же декодеры блоков, что и GEMV `cuda_bd.cuh`, в целочисленной форме CPU (`GQ_EXACT=1`: плавающая форма).
- **Пул хостов**: эксперты, которые оставляет карта, располагаются в отображенной оперативной памяти со страничной блокировкой, которую карта считывает по шине; CPU вычисляет пары небольших шагов на месте (гибрид, `COLI_VK_HYBRID=0` выкл.).- **Пока нет на CUDA:** экспертная таблица плотной цепочки, второе устройство, потоковая передача холодных экспертов подсказки и низкобитные форматы (fmt 200-203). Их используют только сайдкары Qwen3.8, а собственный уровень CUDA Qwen3.8 передает только эксперты FP8: сборка с Vulkan также передает экспертов сайдкаров на уровень Vulkan на той же карте ([qwen38.md](qwen38.md#routed-experts-as-int4-g64)).
- **GLM-5.3 Flash, DeepSeek V4.1 и MiMo** (`COLI_CUDA=1`, без уровня Vulkan): устройство CUDA открывается для перенаправленных экспертов, поскольку их удерживает их контрольная точка или GGUF. Их плотные матрицы передаются на ту же карту, где они помещаются (ниже, `cu_dense.h`): резидентные матрицы GLM-5.3, GGUF DeepSeek V4.1 и блоки MiMo в блоках f32, int8 или GGUF (его bf16 и FP8 остаются на CPU). Сборка с Vulkan также запускает эти движки на Vulkan, кроме `COLI_VULKAN=0`, поскольку плотная цепочка Vulkan выполняет работу слоя над картой за один кадр. `tests/cuda_tier_engines.sh` запускает каждый из этих движков и Kimi K3 на своем крошечном приспособлении против своего процессора, работающего на карте CUDA (токены, оракул DeepSeek V4.1, логиты Kimi K3).
- **Kimi K3** (`COLI_CUDA=1`, `K3_CUDA=1`, без уровня Vulkan): перенаправленные эксперты, MXFP4 контрольной точки или блоки GGUF, находящиеся на уровне из истории, с SiTU на карте. Путь для каждого вызова, по которому загружался каждый маршрутизируемый эксперт MXFP4 на каждом этапе декодирования, остается отключенным после включения уровня; специалисты его не брали, запускали на CPU. Его плотные матрицы передаются на карту, где они подходят (ниже), чего нет у UD-IQ1_S 41,6 ГиБ на карте емкостью 24 ГБ. UD-IQ1_S от unsloth (594 ГБ) на RTX PRO 4000 (24 ГБ) с 62 ГБ ОЗУ, промптм на 181 токен и 128 токенами: 0,6 tok/s промпта и 0,26 декодирования против 0,4–0,5 и 0,18–0,22 на CPU и 1,0 и 0,28 на Vulkan, чья цепочка также размещает на карте 45 из 93 слоев; большинство экспертов исходят из диска, который задает темп.
- **DeepSeek V4** (`make deepseek-v4 CUDA=1`, `COLI_CUDA=1` без уровня Vulkan) использует его для экспертов GGUF и помещает плотные матрицы GGUF на ту же карту (ниже).

<a id="the-dense-matrices-on-the-card-a-matrix-at-a-time-cu_denseh"></a>
### Плотные матрицы на карте, по матрице за раз (`cu_dense.h`)

Уровень оставляет плотную часть механизма на CPU, который считывает всю информацию с каждого токена. `cu_dense.h` помещает его на карту уровня: каждая матрица увеличивается при первом использовании в форматах серверной части (f32, строки int8, int4 в группах, блоки GGUF, строки, которые CPU сохраняет, чередуясь по 16 обратно в файл), ее дескриптор в матричной структуре движка и с этого момента запускается там (GEMV для шага декодирования, тензорные ядра плитки для быстрого фрагмента). Его используют DeepSeek V4 и V4.1 (GGUF), Kimi K3, GLM-5.3 и MiMo; `COLI_CUDA_DENSE=0` сохраняет плотную часть CPU.

- **Бюджет:** вся плотная часть, где умещается половина свободной памяти карты меньше `COLI_VK_TIER_RESERVE_GB`, иначе нет, и уровень оставляет это место. Kimi K3 UD-IQ1_S с первыми 16,7 из 41,6 ГиБ на карте (`COLI_CUDA_DENSE_GB`) покинул тир 865 экспертов вместо 3463; доля карты в перенаправленных экспертах упала с 36% до 16,5%, большая их часть пришла с диска, а запрос не завершился за время, необходимое для плотной части на CPU.- **Правила** — это пути Vulkan для каждой матрицы: поток движка, вне регионов OpenMP и только те матрицы, которые сохраняет движок. DeepSeek V4 и V4.1 находят представление GGUF по его адресу (`cud_entry`): V4 в его резидентных слоях, V4.1 для групп `wo_a`, представление создается для каждого вызова; слот перенаправленного эксперта, в котором находится один эксперт, а затем другой, никогда не идет по этому пути.
- `GQ_EXACT=1` также запускает блоки GGUF в плавающей форме на карте (`backend_cuda.cu`), как это делает CPU.

<a id="deepseek-v4-with-a-gguf-on-cuda"></a>
### DeepSeek V4 с GGUF на CUDA

Собственный путь CUDA контрольной точки FP4 отражает только собственные эксперты FP4 и матрицы FP8 и bf16, поэтому под ним эксперты GGUF и его плотная часть оставались на CPU. При `COLI_CUDA=1` уровень выше берет экспертов, а плотные матрицы, которые движок сохраняет резидентными (внимание, компрессоры и индексатор, общий эксперт, голова) переходят на ту же карту, что и блоки файла: GEMV `cuda_bd.cuh` для шага декодирования, плитки тензорных ядер для строк быстрого фрагмента. Движок считывает свои слои при запуске, так что бюджет уровня оставляет им место, и каждая матрица увеличивается при первом использовании. `COLI_CUDA_DENSE=0` сохраняет их в процессоре.

| CUDA, уровень, плотная часть CPU (`COLI_CUDA_DENSE=0`) | 14,0-14,1 tok/s | 4.11-4.19 tok/s |

— CPU считывал плотную часть (791 матрица, 5,98 ГиБ) каждого токена: на нее уходила половина шага декодирования.

## Ядра, которые начинаются, пока заканчивается предыдущее (`COLI_CUDA_PDL`)

Шаг декодирования запускает свои ядра одно за другим в одном потоке: около 800 токенов на
Qwen3.6-35B, 300 на OLMoE. При простом запуске устройство простаивает между двумя из них, пока
устанавливается следующая сетка и последние блоки той, что перед сливом. На см_90 и более поздних версиях
Ядра цепочки запускаются посредством программного зависимого запуска (`coli_launch`,
`backend_gpu_compat.h`): следующее ядро устанавливается, пока заканчивается предыдущее, и его первое
оператор ожидает на устройстве (`griddepcontrol.wait`), пока сетки перед ним не завершится
и их записи видны. Каждое ядро читает и записывает то, что оно сделало после простого запуска, поэтому
каждый результат сохраняет свои биты.

Он охватывает операции цепочки CUDA, GEMV блоков GGUF и внутренние ядра, которых достигает цепочка:
плотные GEMV и GEMM каждого формата, ядра маршрутизированных экспертов, их сорт и их
сумма. HIP, карты до sm_90, сборка, код которой скомпилирован ниже sm_90, и
устаревший поток по умолчанию запускается просто. `COLI_CUDA_PDL=0` делает это везде.

## Примечания и ограничения

- Отчеты о времени в текстовом режиме заполняются отдельно от декодирования.
- Спекуляции MTP по умолчанию отключены на CUDA (маршруты с холодным проектом увеличивают эксперта).
  трафик); явные переопределения `DRAFT=n`. Начиная с #294, `SPEC_PIN=1` сохраняет
  черновики/проверка ядер согласованы, когда есть предположения.
- Устройства используют независимые контексты; ни один эксперт не сегментируется. Ядра
  Кастомные ядра, ориентированные на корректность.
- Качество профиля важнее, чем объем видеопамяти: тот же уровень 150 ГБ.
  измерено 0,94–1,64 tok/s при первом горячем использовании против 0,29 tok/s при заполнении без отвода тепла.
- Уровень графического процессора получает свою видеопамять только тогда, когда процессор является слабым звеном — настроенным
  Процессор AVX-512 может соответствовать процессору 5090 на экспертном уровне
  ([#101](https://github.com/JustVugg/colibri/issues/101)).
