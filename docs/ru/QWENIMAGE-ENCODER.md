# Qwen-Image-2.1 VAE-кодер

Используйте `c/qwenimage_encoder.h`, чтобы кодировать одно изображение RGB или RGBA в нормализованное изображение.
VAE скрыт в процессоре. Кодировщик использует float32 и разделяет код декодера.
свертка, остаточный блок, нормализация RMS, внимание и ядра GEMM.

Для редактирования изображений в интерфейсе командной строки или на сервере по-прежнему требуется видеокодер, ссылка
сборка токенов и подготовка DiT. Это изменение добавляет только кодер VAE.

<a id="interface"></a>
## Интерфейс

```c
QiVaeEncoder *v = qie_load("path/to/vae");
/* Check v, then allocate height/scale * width/scale * z_dim floats. */
int rc = qie_encode(v, pixels, height, width, channels, normalized_latents);
qie_free(v);
```

<a id="checkpoint-and-input"></a>
### Контрольная точка и ввод

`qie_load` читается как `config.json` и `encoder.*` и `quant_conv.*`.
предохранители. Он пропускает веса декодера и свертку с временной понижающей дискретизацией.
веса, которые не используются в однокадровом пути. Он принимает остаток,
непропатченная архитектура Qwen-Image-2.1 и отклоняет неподдерживаемые
конфигурации или отсутствуют необходимые тензоры.

Передавайте плотно упакованные байты HWC RGB или RGBA в `qie_encode`. Кодер RGBA
добавляет непрозрачную альфу к входу RGB и сохраняет предоставленную альфу без
композитинг. Кодер RGB принимает только входной сигнал RGB. Для ввода с плавающей запятой используйте
`qie_encode_f32` со значениями HWC в `[-1, 1]` и настроенным количеством каналов.

Высота и ширина должны быть положительными кратными настроенного пространственного масштаба.
(16 для Qwen-Image-2.1). Неверные размеры или количество каналов возвращаются `-1`
перед доступом к пикселю. Подготовьте размеры перед вызовом энкодера;
он не изменяет размер и не обрезает изображения.

<a id="output"></a>
### Вывод

Выделите `(height / scale) * (width / scale) * z_dim` поплавков. На выходе используется
Порядок HWC и содержит заднюю моду после `quant_conv`, нормализованную как
`(mode - latents_mean) / latents_std`. Отбор проб, упаковка патчей DiT, мозаика,
и многокадровое кэширование находятся за пределами этого интерфейса.

Понижающая дискретизация соответствует
[Диффузоры AutoencoderKLQwenImage21](https://github.com/huggingface/diffusers/blob/80c7ed262aeffbeb43ef13ae04baeb9b84515a69/src/diffusers/models/autoencoders/autoencoder_kl_qwenimage21.py):
свертка шага-2 использует нижнее/правое дополнение и ярлык AvgDown3D
учитывает временной интервал с нулевым заполнением в своем делителе даже для одного изображения.

<a id="reproducible-cpu-checks"></a>
## Воспроизводимые проверки CPU

Запустите примитивные тесты без зависимостей и тесты с недопустимыми входными данными с помощью
`make -C c check` или запустите их самостоятельно:

```sh
make -C c tests/test_qwenimage_encoder
./c/tests/test_qwenimage_encoder
```

Проверка ссылок генерирует небольшие случайные веса в двух потоках CPU и
очищает свои временные фиксации в случае успеха или неудачи. Он не загружает модель
веса. Установите закрепленные эталонные зависимости, включая диффузоры.
коммит, указанный выше, в изолированной среде:

```sh
uv venv --python 3.12 .venv
uv pip install --python .venv/bin/python -r c/tools/requirements-qwenimage-tiny.txt
make -C c qwenimage-encoder-check PYTHON=../.venv/bin/python
# Same checks, with ASan/UBSan on the encoder, plus a saved JSON report:
.venv/bin/python c/tools/check_qwenimage_encoder.py --sanitizers --report encoder-check.json
```

Бегун устанавливает таймаут для каждого подпроцесса и возвращает ненулевой код выхода.
в случае сбоя и записывает команды, выходные данные, состояние и время в формате JSON. Он проверяет:

- Шесть входов RGB/RGBA с разрешением 16×16, 32×48, 48×32 и 80×112, включая одинаковые
  Значения RGB с непрозрачной и прозрачной альфа-каналом.
- Необработанный и нормализованный апостериорный режим, рабочие полосы по умолчанию и минимальные,
  Контрольная точка только для кодировщика, недопустимые конфигурации и отсутствие промежуточного звена
  вес.

Допуск энкодера составляет `1e-4` абсолютную погрешность. Бегун также проверяет
общие ядра для существующего декодера Oracle с его исходным
пороги приемлемости. Работа `qwenimage-tiny-check` CI включает в себя обычные и
Кодер ASan/UBSan работает. LeakSanitizer отключен.

Модульные тесты сборки CPU и кодировщика по умолчанию не требуют ни Torch, ни Diffusers.
Другие тесты `make check` могут использовать дополнительные зависимости при установке.

Эти проверки охватывают численное согласие с небольшими случайными весами. Обученный
контрольные точки, визуальное качество, следование инструкциям по редактированию, непроцессорные серверные части,
пиковая память больших изображений и нисходящее эталонное преобразование остаются непровереннымиздесь. Эти проверки не сопровождаются никакими заявлениями о производительности или отсутствии утечек.
