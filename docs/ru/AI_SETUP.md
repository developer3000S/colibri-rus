# Настройка colibri с помощью помощника по кодированию AI

Эта страница написана для помощника по кодированию с использованием искусственного интеллекта, который пользователь попросил установить.
запустить, проверить или остановить colibri на своей машине. Каждый шаг представляет собой команду с
машиночитаемый результат. Человек тоже может следовать этому; путь в один шаг для
люди — это `START-HERE.bat` (Windows) или `./start-here.sh` (Linux, macOS), см.
[quickstart.md](quickstart.md).

Если ваш клиент использует протокол контекста модели, те же операции
доступен в качестве инструментов: см. [MCP_SERVER.md](MCP_SERVER.md).

<a id="ground-rules"></a>
## Основные правила

- **Спросите перед загрузкой.** Модели емкостью от 19 ГБ до 1,6 ТБ. Покажите пользователю
  рекомендуемую модель, ее размер и место, где она будет размещена, и получите утвердительный ответ.
- **Спросите перед установкой системных пакетов.** Установка никогда не запускается `sudo`,
  `apt`, `pacman` или `winget`. Когда ему нужен пакет, он печатает
  точная команда; покажите его пользователю и запускайте только с его согласия.
- **Повторные запуски безопасны.** Каждый шаг идемпотентен. Если команда останавливается (сеть,
  timeout, Ctrl+C), запустите ту же команду еще раз: она продолжится с того места, где остановилась.
- **Предпочитайте диск с Linux на WSL.** Никогда не устанавливайте модель ниже `/mnt/c` (или любого другого
  `/mnt/<drive>`): движок передает модель с диска, и этот путь
  во много раз медленнее. По умолчанию `~/colibri-models` верно.

<a id="0-prerequisites"></a>
## 0. Предварительные условия

Python 3.10 или новее и копия репозитория.

```bash
python3 --version                              # Windows: py -3 --version
git clone https://github.com/JustVugg/colibri  # or use the folder the user already has
cd colibri
```

В Windows выполните приведенные ниже команды из PowerShell или cmd в репозитории.
папка с `py -3 c\coli` там, где на этой странице написано `python3 c/coli`. Если Python
отсутствует в Windows, `winget install -e --id Python.Python.3.12 --scope user`
устанавливает его для текущего пользователя (сначала спросите).

Компилятор C не является обязательным. С одним (gcc и make в Linux, инструменты Xcode в
macOS, MSYS2 UCRT64 в Windows) движок создан для этой машины с
Графический процессор, когда он пригоден для использования. Без него, готовый движок с GitHub.
используется релиз, который работает на процессоре.

<a id="1-look-at-the-machine"></a>
## 1. Посмотрите на машину

```bash
python3 c/setup_hw.py --json             # RAM, disk, CPU features, GPUs
python3 c/coli setup --list --json       # every model against this machine
```

`setup_hw.py --json` отчеты `memory.total` и `memory.available` (байты),
`disk.free_bytes` вместо `~/colibri-models` (передать другую папку в качестве аргумента),
`cpu.features`, `gpu.vulkan` (устройство Vulkan, которое будет использовать движок, с его
`type`, `integrated` или `discrete` и `budget_bytes` или `device_local_bytes`),
`gpu.vulkan_icd` (манифест драйвера находится в домашней папке, обычно на
WSL) и `gpu.nvidia` (от nvidia-smi, каждая карта имеет свой `compute_cap`,
например `7.0` или ноль, если об этом ничего не сообщалось).

`setup --list --json` возвращает один объект для каждой модели:

| Поле | Значение |
|---|---|
| `id` | что нужно `--model` |
| `download_gb` | размер загрузки |
| `ram_min_gb`, `ram_good_gb` | ниже первого он не бежит; со второго он работает как измерено |
| `dense_gb` | та часть, которая всегда остается в оперативной памяти |
| `runs` | `from RAM` (маленькие модели) или `streams experts from the SSD` (большие) |
| `status` | `good`, `tight`, `needs-ram`, `needs-disk` или `unsupported` |
| `fits`, `reason` | можно ли его сюда установить и почему |
| `recommended` | ровно одна модель используется по умолчанию |

«Подходит» означает: плотная часть, которая всегда остается в оперативной памяти, плюс минимум
Кэш эксперта умещается в оперативной памяти, а загрузка умещается на диске.

Сообщите пользователю рекомендации и подходящие альтернативы с указанием их
размеры. Большие модели выполняют потоковую передачу с SSD и работают намного медленнее, чем маленькие.
те, которые работают из оперативной памяти.

<a id="2-install"></a>
## 2. Установить

Неинтерактивный, с моделью, выбранной пользователем:

```bash
python3 c/coli setup --yes --model qwen36-35b --no-start
```

Что он делает по порядку: определяет оборудование, выбирает сборку движка (см.
[Как выбирается сборка движка](#how-the-engine-build-is-chosen)), строит или
извлекает движок, загружает модель с резюме, запускает планировщик нафайлы и записывает конфигурацию запуска. Он печатает каждый шаг.

Загрузка может занять несколько часов. Если у вашего исполнителя команд есть ограничение по времени, запустите
он отключился и опрашивает статус вместо ожидания:

```bash
# Linux, macOS, WSL
nohup python3 c/coli setup --yes --model qwen36-35b --no-start > colibri-setup.log 2>&1 &
```

```powershell
# Windows
Start-Process -WindowStyle Hidden py -ArgumentList '-3','c\coli','setup','--yes','--model','qwen36-35b','--no-start' `
  -RedirectStandardOutput colibri-setup.log -RedirectStandardError colibri-setup.err
```

Затем опрашивайте каждую минуту или около того:

```bash
python3 c/coli status --json
```

`install.phase` перемещается через `build`, `download`, `ready` (настроено) и
`started` (сервер запущен); `error` и `interrupted` заканчивают его раньше, и
`install.running` сообщает, активен ли процесс установки. Во время
скачать `install.done` и `install.total` — это байты, а `install.rate` — это
байт в секунду. На `error`, `install.message` написано, почему; устраните причину и
повторите ту же команду установки.

<a id="the-setup-options"></a>
### Параметры настройки

| Вариант | Эффект |
|---|---|
| `--yes`, `-y` | вопросов нет: рекомендации и все по умолчанию |
| `--model ID` | модель для установки (id из `--list`) |
| `--model-dir DIR` | использовать модель, уже имеющуюся на диске, вместо загрузки |
| `--dir DIR` | где загружаются модели (по умолчанию `~/colibri-models`) |
| `--backend auto\|cpu\|vulkan\|cuda` | принудительно собрать движок (`auto`: см. ниже); `--no-gpu` это `--backend cpu` |
| `--host H`, `--port N` | где сервер прослушивает (по умолчанию `127.0.0.1:8000`) |
| `--ctx N` | контекст, с которого запускается сервер, сохраняется в течение `coli start` (по умолчанию: автоматически, из памяти); повторный запуск с `--ctx` на завершенной настройке меняет его, `--ctx 0` восстанавливает автоматически, а прерванная настройка сохраняет выбор |
| `--no-start` | остановиться после записи конфигурации |
| `--background` | запустить сервер в конце отсоединенным |
| `--no-browser` | не открывать вкладку браузера |
| `--reconfigure` | выбрать еще раз, даже если настройка завершена |
| `--list`, `--all` | показать каталог этой машины и выйти |
| `--via-windows auto\|yes\|no` | Только WSL: загрузка через Windows' `curl.exe` |
| `--no-verify` | пропустить контрольные суммы загруженных файлов |
| `--json` | машиночитаемый результат (подразумевает `--yes` и фоновый старт) |

Конфигурация запускает сервер с `--auto-tier`, поэтому эксперт кэширует
Отпечатки линий `Plan:` (и профиль `coli tune`) — это те, которые получает движок:
на CUDA для каждой модели, на Vulkan и процессоре для семейств с фиксированным значением по умолчанию
кэш (Qwen3.6, Qwen3.8, Kimi K3, Inkling, DeepSeek V4 и V4.1, MiMo). ГЛМ
движки и OLMoE сами там размерят свой кэш. Настройка, написанная до этого
запускали движок Vulkan или CPU этих семейств по умолчанию (восемь слотов на слой для
Qwen3.6), и `coli start` теперь добавляет к нему флаг.

При завершенной настройке явные `--backend`, `--no-gpu`, `--host` и `--port`.
обновить сохраненную конфигурацию для той же модели. Варианты, оставленные без внимания, сохраняют свои
сохраненные значения.

<a id="how-the-engine-build-is-chosen"></a>
### Как выбирается сборка движка

С `--backend auto` (по умолчанию):

1. **CUDA** для карты NVIDIA, если все эти условия выполняются:
   - движок имеет путь CUDA в Linux: Qwen3.6 (с Qwen3-Coder и
     Qwen3.8-27B), Qwen3.8 Flash Next, GLM-5.2/5.3 (движок `colibri`; не
     GLM-5.3-Flash), Kimi K3, Inkling и DeepSeek V4 Flash;
   - установлен набор инструментов CUDA (`nvcc`);
   - набор инструментов здесь создается для каждой карты NVIDIA. Вычисление карты
     возможности исходят из `nvidia-smi` (`gpu.nvidia[].compute_cap` в
     `setup_hw.py --json`, например `7.0` для V100). Список инструментов
     происходит от `nvcc --list-gpu-arch`, или тоже из его версии для nvcc
     стар, чтобы ответить. В CUDA 13 исключены Maxwell, Pascal и Volta (вычисления 5.x для
     7.2), а Blackwell (вычислительная версия 12.0) требуется CUDA 12.8 или новее;
   - собственный код CUDA движка поддерживает карту и набор инструментов.
     DeepSeek V4 Flash требует вычислений 6.0 или новее и CUDA 12.0 или новее, иниже CUDA 12.8 установка строит его с помощью `NO_TC=1`.
2. **Vulkan**, когда ответил графический процессор Vulkan, заголовки Vulkan и `glslc`
   установлены. На интегрированном графическом процессоре, который использует оперативную память центрального процессора, только
   там движки измерялись быстрее (сегодня Qwen3.6, Qwen3-Coder и Qwen3.8)
   используйте его, если только `--backend vulkan` не попросит об этом.
3. **CPU** в противном случае.

Если инструментарий не может выполнить сборку для карты, установка не пытается. Там написано
зачем и что устанавливать, и берет следующий бэкенд:

```
Engine: qwen36 with VULKAN (the CUDA 13.0 toolkit cannot build for the Tesla V100-SXM2-16GB (compute 7.0, dropped in CUDA 13): using Vulkan; install a CUDA 12.x toolkit for the CUDA path)
```

С помощью `--backend cuda` та же самая проверка останавливает установку перед любой сборкой, при этом
та же причина. `--backend auto` затем переходит к следующему серверу.

Если сборка по-прежнему не удалась, программа установки распечатает конец журнала и его
путь, затем переходит к следующему бэкэнду: CUDA, затем Vulkan, затем CPU. С
кто-то на терминале спрашивает первым; с `--yes` он идет вперед. Установка
Возобновлено позже не повторяет попытку серверной части, сборка которой не удалась. Неудачная сборка процессора
останавливает установку. Каждый бэкэнд имеет свой собственный журнал, `logs/build-cuda.log`,
`logs/build-vulkan.log` или `logs/build-cpu.log`, поэтому журнал неудачных попыток
build все еще существует после отката.

<a id="when-a-gpu-package-is-missing"></a>
### Когда пакет графического процессора отсутствует

Если на машине есть графический процессор, который сборка еще не может использовать, настройка продолжается.
на процессоре и печатает строку типа:

```
  to use the GPU through VULKAN, first run:  sudo apt install libvulkan-dev glslc mesa-vulkan-drivers
```

Покажите эту команду пользователю. Если они его запустят (или позволят вам запустить), бегите
`python3 c/coli setup --yes --no-start` еще раз: установка запоминает, что графический процессор
ждал пакеты, видит что они есть, пересобирает движок на
графический процессор и переписывает конфигурацию. Загрузка не повторяется.

В Windows для сборки графического процессора требуется MSYS2 с пакетами UCRT64; названия строк
их. Предварительно встроенный движок Windows работает на процессоре.

<a id="wsl"></a>
### ВСЛ

Установка измеряет скорость загрузки из WSL и из Windows с помощью короткого
ранжированный запрос, когда объем загрузки превышает несколько ГБ. Если Windows много
быстрее (может быть: 63 КБ/с против 3,3 МБ/с было замерено на одной машине), это
загружается через Windows `curl.exe` в ту же папку Linux. Заставьте это с помощью
`--via-windows yes` или отключите его с помощью `--via-windows no`.

Драйвер Vulkan, установленный вручную в домашней папке (драйвер Mesa's Dozen
обычный на WSL) находится и записывается в конфигурацию запуска как
`VK_ICD_FILENAMES`.

<a id="3-start"></a>
## 3. Старт

```bash
python3 c/coli start --background --no-browser
python3 c/coli status --json
```

Подождите, пока `server.state` не станет `ready` (сначала `loading`; загрузка занимает от
от секунд до минут в зависимости от модели). Затем дайте пользователю:

| Поле в `status --json` | Использование |
|---|---|
| `server.urls.browser` | приборная панель для пользователя |
| `server.urls.openai_base_url` | `.../v1`, для клиентов, совместимых с OpenAI |
| `server.urls.anthropic_base_url` | для клиентов, совместимых с Anthropic (добавлены `/v1/messages`) |
| `server.model_id` | значение `model`, которое должны отправлять запросы API |
| `server.tokens_per_second` | скорость последнего ответа, включая время ответа |

Быстрая проверка того, что он отвечает:

```bash
curl -s http://127.0.0.1:8000/v1/chat/completions -H 'Content-Type: application/json' \
  -d '{"model": "<server.model_id>", "messages": [{"role": "user", "content": "Hello"}]}'
```

`python3 c/coli start` без `--background` работает на переднем плане и открывается
браузер: это то, чего хочет человек, а не вызов инструмента.

Если настроенный порт занят другой программой, сервер переходит в
следующий свободный порт и конфигурация обновляется; прочитать URL-адреса из
`status`.

<a id="4-check-read-the-logs-stop"></a>
## 4. Проверить, прочитать логи, остановиться

```bash
python3 c/coli status          # human-readable; --json for the fields above
python3 c/coli logs -n 50      # server log of a background start (a foreground one prints to its terminal)
python3 c/coli logs --install  # log of a detached install
python3 c/coli stop            # stops the configured server and its engine
```

`coli stop` без `--port` останавливает сервер, настроенный настройкой. Повторный запуск
`python3 c/coli setup` позже запускает настроенный сервер напрямую (в
передний план; добавьте `--background --no-browser` для отдельного начала), без
скачать. Прежде чем запуститься, `make` обновляет движок с помощью исходных кодов:делать нечего (долю секунды), если только они не изменились, как после `git pull`,
и тогда восстанавливается только то, что изменилось. `coli start` делает то же самое.

<a id="files"></a>
## Файлы

Все, что пишет установка, живет в одной папке: `~/.local/share/colibri` на
Linux, `~/Library/Application Support/colibri` на macOS,
`%LOCALAPPDATA%\colibri` в Windows. `COLI_SETUP_HOME` переопределяет его.

| Файл | Содержание |
|---|---|
| `setup.json` | конфигурация запуска: модель, движок, серверная часть, среда, аргументы средства запуска, URL-адреса |
| `install-state.json` | фаза и ход текущей или последней установки |
| `logs/serve.log`, `logs/install.log`, `logs/build-<backend>.log` | журналы (один журнал сборки для каждой серверной части: `cuda`, `vulkan`, `cpu`) |
| `runtime/` | готовая версия, когда нет компилятора |

В папке модели находится номер `.colibri-download.json`, в котором перечислены файлы и
говорит, что загрузка завершена. Частичные файлы заканчиваются на `.part`.

`HF_TOKEN` (или сохраненный токен `hf auth login`) используется для закрытых репозиториев.
`HF_ENDPOINT` указывает на зеркало для загрузки.

<a id="troubleshooting"></a>
## Устранение неполадок

| Симптом | Что делать |
|---|---|
| `download stopped: ...` | повторите ту же команду; возобновляется с байтов на диске |
| `checksum mismatch` | частичный файл был удален; повтор |
| `needs N GB free for the download` | пройти `--dir` с папкой на диске большего размера |
| `the published release ... predates <model>` | компилятора нет, и последняя версия не может запустить эту модель: установите компилятор (сообщение называет команду) или выберите другую модель |
| `... toolkit cannot build for the <card> (compute X.Y, ...)` | для настройки потребовался Vulkan или CPU; для CUDA установите набор инструментов для имен строк и повторите запуск с помощью `--reconfigure` |
| `the <engine> CUDA build failed (full log: ...)` | установка перенесена на следующий бэкенд; в журнале указано, почему сборка CUDA не удалась |
| `Already set up: ...` но пользователь хочет другую модель | `--reconfigure` или `--model ID` |
| `server.state` остается `loading` | `coli logs -n 50`; большие модели загружаются за несколько минут |
| `plan warning: RAM budget cannot hold one expert slot` | модель не помещается в свободную оперативную память: закройте программы или выберите меньшую модель |
