# Многодисковая потоковая передача

Используйте дополнительные приводы, когда модель считывает вывод о пределе. `COLI_MODEL_MIRROR` баллов
для доступных только для чтения копий осколков основной модели; настройка RAID не требуется.
Эти примеры предназначены для движка GLM-5.2. Другие движки имеют собственный ввод/вывод.
пути, поэтому проверьте направляющие модели, прежде чем применять те же настройки.

<a id="run-with-two-or-more-copies"></a>
## Запуск с двумя или более копиями

Запускайте из `c/` при извлечении исходного кода или из каталога, содержащего `coli` в
распакованный релиз. Замените пути существующими копиями модели.

Bash, с одним основным и двумя зеркалами:

```bash
COLI_MODEL_MIRROR='/mnt/nvme2/glm52_i4;/mnt/nvme3/glm52_i4' \
  python3 ./coli chat --model /mnt/nvme1/glm52_i4
```

PowerShell с той же компоновкой трех дисков:

```powershell
$env:COLI_MODEL_MIRROR = 'E:\models\glm52_i4;F:\models\glm52_i4'
python ./coli chat --model 'D:\models\glm52_i4'
```

Для двух дисков укажите только один зеркальный каталог. Цитировать список: нецитируемый
точка с запятой разделяет команды оболочки. Первичное питание осуществляется от `--model`
(или `COLI_MODEL`); не повторяйте его в списке зеркал.

Если `COLI_DISK_WEIGHTS` не установлено, механизм проверяет полосу пропускания при запуске и печатает
измеренное разделение. Необязательное переопределение представляет собой список положительных значений, разделенных запятыми.
относительные веса, сначала основное, затем каждое пригодное к использованию зеркало в порядке списка.
Например, `9,3,3` запрашивает долю в 60%, 20% и 20% на трех дисках;
это не измеренное ускорение. Проверьте журнал запуска на наличие пропущенных зеркал и
проверяйте сбои, прежде чем доверять расколу. См.
[ссылка на среду](ENVIRONMENT.md#dual-ssd-streaming) для переменных.

Отсутствующие или расходящиеся осколки зеркала возвращаются к основному. Для меньшего
езжайте, используйте [планировщик частичного зеркала](#partial-mirrors-coli-mirror)
для подготовки подмножества с рейтингом использования. `COLI_MODEL_DIRS` — другая раскладка: она
распределяет отдельные сегменты по дискам для объединения емкости, а не для добавления
копии тех же осколков.

Подробности, которые стоит знать:

- зеркало **проверяется при запуске** (размер каждого файла + заголовок защитных экранов должны быть
  быть байтово-идентичным первичному); расходящиеся или отсутствующие файлы остаются на
  основной, поэтому **частичное зеркало подойдет**: второй SSD меньшего размера может служить
  осколки, которые он держит;
- на зеркале **никогда не написано**: `.coli_usage`, `.coli_kv` и все коляски остаются
  на первичном;
- ошибка чтения на зеркале возвращается на первичное (одно предупреждение, без сбоев), поэтому
  отключение второго диска в середине работы ухудшает работу сервера, а не убивает его;
- буферизованное чтение использует детерминированную экспертную маршрутизацию; подходящие прямые чтения могут
  разбить одного эксперта по репликам;
— маршрутизация никогда не меняет токены, поскольку обе копии побайтно идентичны; включить
  `PROF=1` для счетчиков профиля `MIRROR:`, показывающих ГБ, обслуженных на диск.

<a id="partial-mirrors-coli-mirror"></a>
## Частичные зеркала: `coli mirror`

Для второго диска, который не может вместить всю модель, Colibri может считаться частичной.
зеркало из экспертной истории, которую он уже усвоил. Запустите несколько представителей
сначала подсказки, чтобы `.coli_usage` отражал рабочую нагрузку, затем планируйте, поэтапно и
проверьте зеркало:

```bash
./c/coli mirror plan  --model /fast/glm52_i4 --mirror /second/glm52_i4 \
  --budget-gib 200 --reserve-gib 20
./c/coli mirror stage --model /fast/glm52_i4 --mirror /second/glm52_i4 \
  --budget-gib 200 --reserve-gib 20
./c/coli mirror verify --model /fast/glm52_i4 --mirror /second/glm52_i4
```

Планировщик напрямую считывает заголовки защитных датчиков, следует за каталогами разделенной модели.
с `COLI_MODEL_DIRS` и отдает приоритет шардам, которые могут обслуживать самые горячие маршруты
эксперты. Постановка никогда не меняет первичную модель: она копируется через временную модель.
файлы, сохраняет запрошенный резерв свободного места, проверяет каждый шард с помощью
SHA-256 никогда не удаляет существующий фрагмент зеркала и автоматически публикует
получение только после того, как выбранное зеркало будет готово.

<a id="what-has-been-measured"></a>
## Что было измерено

Увеличение пропускной способности хранилища не приводит непосредственно к увеличению количества токенов в секунду.Вычисления, резидентность кэша и общая пропускная способность PCIe/контроллера могут доминировать.
Сравните всю рабочую нагрузку вывода, а не только тест привода.

- **Помогли два независимых диска NVMe.** Отчет Threadripper PRO 7965WX в
  [#1249](https://github.com/Developer3000S/colibri-rus/issues/1249), также записано в
  [эталонная таблица](benchmarks.md), измерено от 0,80 до 1,10 tok/s (+37,5%)
  с `DIRECT=1`; буферизованное сравнение набрало около 16%.
- **Для накопителей со смешанной скоростью обнаружена ошибка, которая впоследствии была исправлена.**
  [#1270](https://github.com/Developer3000S/colibri-rus/pull/1270) заменено на равный размер
  полосы с фрагментами, взвешенными по полосе пропускания. Перед этим исправлением добавление диска SATA
  на два накопителя NVMe уменьшено время декодирования GLM-5.2 с 0,900 до 0,666 tok/s в
  сообщил об эксперименте. Это историческое свидетельство, а не текущий спад
  присваивается каждому зеркалу SATA.
- **Третий диск после исправления был нейтральным на этом хосте.** Автор
  [продолжение `dev`](https://github.com/Developer3000S/colibri-rus/pull/1270#issuecomment-5466324415)
  сообщило 1,030tok/s с двумя дисками NVMe и 1,006 с добавленным диском SATA.
  (пять чередующихся прогонов на группу, зарегистрированные стандартные отклонения 0,041 и 0,034).
  Автор оценивал разницу в пределах вариаций от серии к серии. Это окно
  11/i9-14900K/RTX 3090 результат не обещает выигрыша от более медленного диска
  на другой машине.

Это измерения сообщества для конкретных конфигураций, а не новые результаты.
из этого руководства. [#1137](https://github.com/Developer3000S/colibri-rus/issues/1137) содержит
обсуждение нескольких дисков и более ранний отчет о смешанной скорости.

<a id="compare-against-one-drive"></a>
## Сравнить с одним диском

1. Запишите коммит, модель/контейнер, аппаратное обеспечение и расположение диска/контроллера.
   Сохраняйте промпт, начальное число, лимит выходных токенов, бюджеты RAM/VRAM и режим ввода-вывода.
   исправлено. Держите фоновый диск в режиме ожидания. Используйте ту же историю использования
   и подготовку кэша для каждого рукава, а также отчеты о холодных и теплых запусках отдельно.
2. Запустите новый процесс для каждой руки. Для базового уровня только для первичной очистки очистите
   `COLI_MODEL_MIRROR`, его устаревший псевдоним `SNAP_MIRROR` и любой
   `COLI_DISK_WEIGHTS` переопределение. Для кронштейна зеркала установите только
   `COLI_MODEL_MIRROR` к тестируемым копиям и позвольте зонду выбрать
   веса. Оставьте любой макет `COLI_MODEL_DIRS` фиксированным; если он охватывает диски, отметьте
   это базовая версия с разделенной компоновкой, а не с одним приводом.
3. Установите `PROF=1` на обоих плечах. Сохранение стартовых `[MIRROR]` сообщений, пропускной способности,
   TTFT, экспертный коэффициент попадания и счетчики `MIRROR:` байт/чтений на диск. ГЛМ
   Цикл обслуживания выдает счетчики накопительного профиля при чистом завершении работы; не делай
   предположим, что они появляются после каждого ответа в чате.
4. Чередуйте не менее трех повторений на каждую руку. Сообщите медиану и
   распространение, проверки вывода/корректности и необработанные журналы, включая исключенные прогоны.
   При тестировании `DIRECT=1` запустите его как отдельное сравнение и убедитесь, что
   платформа и файловая система фактически используют прямой ввод-вывод. См.
   [протокол сравнительного тестирования](benchmarking.md) для правил состояния кэша и отчетов.

Чтобы вернуться к первичной конфигурации в вашей оболочке:

```bash
unset COLI_MODEL_MIRROR SNAP_MIRROR COLI_DISK_WEIGHTS
```

```powershell
Remove-Item Env:COLI_MODEL_MIRROR, Env:SNAP_MIRROR, Env:COLI_DISK_WEIGHTS -ErrorAction SilentlyContinue
```

Назначения PowerShell `$env:` сохраняются в этом сеансе; удалите `PROF`, если
вы включили его только для этого сравнения.
