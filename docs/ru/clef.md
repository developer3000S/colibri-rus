# Ключ на colibri

[Clef](https://huggingface.co/Cloudflare/clef) от Cloudflare (Apache-2.0)
модель решения: дайте ей состояние (текст или JSON) и введите вопросы
(`choice`, `score`, `noul`) и возвращает вероятность для каждого варианта
каждый вопрос за один проход вперед. Это Qwen3.8-27B, прошедший обучение, плюс
небольшой преобразователь, голова объединенной схемы, которая считывает последние данные магистрали.
скрытые состояния. На карточке модели указано, что API совместим с Jev и System.
Один.

colibri запускает его на движке qwen36, на котором уже работает Qwen3.8-27B:
`POST /v1/systemone` нативно отвечает руководитель, с просьбой и
ответ Jev API TypeSafe ([systemone.md](systemone.md)), и то же самое
процесс все еще общается.

<a id="download-convert-serve"></a>
## Скачивайте, конвертируйте, обслуживайте

```sh
hf download Cloudflare/clef --local-dir ~/Models/clef          # 55 GB, bf16
python3 c/tools/convert_qwen36.py --model ~/Models/clef --out ~/Models/clef_c
make -C c qwen36
./c/coli serve --model ~/Models/clef_c
```

Конвертер записывает бэкбон как для Qwen3.8-27B (контейнер f16,
52 ГБ) и копии `joint_head_config.json` и `joint_head.safetensors` рядом.
это. `coli` распознает контейнер qwen36, содержащий оба файла, как Clef:
на баннере написано `Clef · 27B`, идентификатор модели API — `clef`, `coli info` добавляет
линия `decision`, `coli doctor` проверяет соответствие головы позвоночнику и
`/v1/models` списки `capabilities: ["chat", "systemone"]`.

Костяк Клефа не штатный: сравнил тензор за тензором с
Qwen/Qwen3.8-27B, слои от 0 до 39, вложения, голова LM и зрение
башни идентичны, а матрицы проекций 186 и MLP слоев от 40 до
63 отличаются. Контейнер Qwen3.8-27B не может его заменить.

```sh
curl -s localhost:8000/v1/systemone -H 'Content-Type: application/json' -d '{
  "model": "clef",
  "state": "Our checkout started returning errors and orders are blocked.",
  "questions": {
    "department": {"type": "choice", "instructions": "Which team should handle the message?",
                   "criteria": {"billing": "Payments or invoices", "technical": "Bugs or outages"}},
    "urgency": {"type": "score", "criteria": ["Can wait", "This week", "Today"]},
    "outage": {"type": "noul", "instructions": "Is a service down?"}}}'
```

```json
{"id": "req_973f...", "model": "clef", "provider": "colibri",
 "answers": {
   "department": {"type": "choice", "choice": "technical",
                  "probabilities": {"billing": 0.075526, "technical": 0.924474}, "confidence": 0.848948},
   "urgency": {"type": "score", "score": 1.837707, "legend": {"0": "Can wait", "1": "This week", "2": "Today"},
               "probabilities": {"0": 0.038915, "1": 0.084464, "2": 0.876622}, "confidence": 0.814932},
   "outage": {"type": "noul", "noul": 0.86562}},
 "usage": {"input_tokens": 300, "output_tokens": 0, "cost": 0}}
```

`input_tokens` — длина отображаемой записи, каждый вопрос в одном
последовательность.

<a id="what-the-engine-computes"></a>
## Что вычисляет движок

Каждый шаг соответствует собственной контрольной точке `joint_schema_model.py` (ревизия
2f3de3dd, SHA-256 0e304cf7...), что является спецификацией:

| шаг | ссылка | в colibri |
|---|---|---|
| запись | `systemone` | шлюз отправляет запись в необработанном виде (`CAPS decide_record=raw`): значения вызывающего абонента, JSON с отсортированными ключами, ничего по умолчанию |
| рендеринг | `encode_record`, `question_options`, `render` | `clef_head.h` `clef_render`: системное промпт, `STATE:`, затем по каждому вопросу `FIELD`, `ID`, `TYPE`, `INSTRUCTION` (идентификатор вопроса, если его нет) и по одному `OPTION k:` на каждый вариант как `{"description":...,"option_id":...}`; noul `true`, затем `false` с описаниями по умолчанию, отсортированными метками выбора, уровнями баллов по порядку; каждая часть токенизирована сама по себе, государство обрезало ее конец, чтобы соответствовать `max_length` 16384 |
| токенизатор | `tokenizer.json`, трансформеры `Qwen2Tokenizer` | BPE qwen36 с точными классами Unicode и NFC для контрольной точки Clef; регулярное выражение — это то, которое применяется контрольной точкой, если знак объединения не является частью набора букв |
| позвоночник | `Qwen3_5Model` (текстовый путь) | предварительное заполнение qwen36 всей записи, сохраняющее окончательно нормализованное скрытое состояние каждой позиции |
| голова | `JointSchemaHead.forward` | `clef_head_forward`: LayerNorm для скрытых состояний, средства охвата для инструкций и опций, векторы лексических опций из строк заголовка LM (читаются с точностью контейнера, а не копии int8), два слоя маршрутизации доказательств (опции, относящиеся ко всей последовательности), сводка опций для каждого вопроса, четыре слоя декодера над полями, затем `prior + sigmoid(gate) * (scale * cosine + residual)` |
| ответ | `systemone` | softmax за вопрос; шлюз формирует ответ Jev (`choice`, `score` как ожидаемый уровень, `noul` как P(истина)) |

Голова работает в ф32 (512 Мб). Основа имеет одну из трех ширины:
`COLI_DENSE_BITS`:

| ширина | ОЗУ (измеренное RSS) | точность по сравнению с эталоном | скорость |
|---|---|---|---|
| f16 (`16`): собственные значения контейнера | 55,4 ГБ | макс \|дп\| 0,012 | 47,4 с на запрос |
| int8 (`8`) | 29 ГБ | макс \|дп\| 0,22 | 20,4 с || int4 (`4`) | 19 ГБ | макс \|дп\| 0,22 | 30,2 с |

**Какой из них работает.** Если вы установите `COLI_DENSE_BITS`, то этот. В противном случае `coli
подача`, `coli веб` and `coli чат` ask the planner (`coli план` показывает то же самое
числа): когда его бюджет ОЗУ удерживает магистраль в сохраненном размере плюс
времени выполнения и состоянии KV 16384 токенов, Clef работает в f16, ширине, которая
ответы типа релиза; когда это не так, int8, и шлюз говорит, какой именно
запуск:

```
[clef] dense trunk in int8: f16 would need 58.9 GiB, the budget is 53.3 GiB (COLI_DENSE_BITS=16 to force it)
```

Поля планировщика обычные: на тестовом боксе 61 ГБ f16 работал на скорости
55,4 ГБ, но планировщик там сохраняет его в int8. Коробка с примерно 72 ГБ свободно
по умолчанию получает f16. Движок, запущенный вручную (`SERVE=1 ./qwen36`), остается на
int8, если не указано иное.

<a id="checked-against-the-reference"></a>
## Проверено по ссылке

- **Крошечный оракул** (`make -C c clef-tiny-check`, в CI): случайная контрольная точка.
  в макете релиза (`tools/make_clef_tiny.py`, numpy) и что такое Клеф
  на него отвечает собственный код с трансформерами 5.10.2 в ф32
  (`clef_tiny/ref.json`, автор `tools/make_clef_ref.py`): 16 случаев, 44
  вопросы, каждый тип, от 1 до 40 вариантов, пустые, пустые описания и описания в формате JSON,
  отсутствуют критерии, нулевые или отсутствуют, инструкции и состояния JSON,
  разговоры, добавлены токены и NFC-разложенный текст в состоянии, вырезан
  на `max_length` и схема, которая не подходит. Входные идентификаторы и диапазоны
  идентичны, 44/44 решения идентичны, макс |dp| 2,1е-6 (допуск 2е-5),
  затем то же самое приспособление до `coli serve` и обоих TypeSafe SDK.
- **Настоящая контрольная точка** (`tools/compare_clef.py`, Ryzen 7 8700GE, 8
  темы): 15 запросов, 39 вопросов (примеры карточек моделей, Jev
  примеры этих документов, контракт, разговор, юникод, JSON,
  выбор из 20 намерений, девять вопросов в одной записи) по коду релиза
  в bf16 своя точность:

| костяк движка | входные идентификаторы | решения | макс \|дп\| | запросы до 0,01 |
|---|---|---|---|---|
| f16 (`COLI_DENSE_BITS=16`) | 15/15 идентичны | 39/39 | 0,012 | 14/15 |
| int8 | 15/15 идентичны | 39/39 | 0,22 | 15 августа |
| int4 (`COLI_DENSE_BITS=4`) | 15/15 идентичны | 39/39 | 0,22 | 15 сентября |

  Разрыв - это ствол int8, а не рендер или голова: с тем же
  рендеринг, тот же главный код и f16 контейнера имеют наибольший вес
  разница падает с 0,22 до 0,012 (запись счета-фактуры из девяти вопросов), и
  вердикт проверки кода, который переместился на 0,22 в int8, переместился на 0,0008. Что
  оставленный в f16, является эталонным вычислением в bf16, где движок вычисляет
  в ф32. На крошечном приспособлении, где обе стороны используют f32, веса f16 дают
  макс |дп| 2.5e-6 и int8 5.0e-2.

<a id="speed"></a>
## Скорость

Измерено на том же боксе, 8 потоков, каждый запрос из холодного состояния:

| | по запросу |
|---|---|
| engine, f16, медиана по 15 запросам (от 150 до 779 токенов) | 47,4 с |
| движок, int8, те же запросы | 20,4 с |
| движок, int4, те же запросы | 30,2 с |
| ссылка, bf16, трансформаторы 5.17 на CPU, 28 из 64 слоев читаются с диска | 10,8 с |
| `coli serve`, int8, запрос выше (300 токенов), у клиента | 20,6 с, из них шлюз 1,4 мс |

Время — это предварительное заполнение магистрали; Ядра эталонной матрицы bf16:
на этом процессоре быстрее, чем предварительное заполнение int8 в qwen36, int4 медленнее, потому что
prefill привязан к вычислениям, а f16 умножается на f32. Собственное время движка
в заголовке `x-colibri-engine-ms`.

<a id="knobs"></a>
## Ручки

| переменная | по умолчанию | смысл |
|---|---|---|| `COLI_DENSE_BITS` | f16, если бюджет планировщика позволяет, иначе int8 (см. выше) | `16`, `8` или `4`; `COLI_DENSE_INT4` как для Qwen3.8-27B ([qwen36.md](qwen36.md#the-dense-27b)) |
| `COLI_CLEF_MAX_LEN` | 16384 | `max_length` ссылки: состояние обрезается по размеру, схема длиннее, чем 422 |
| `Q36_MAXT` | 16384 для контрольно-пропускного пункта Клеф (8192 для остальных) | контекст движка. Строки KV распределяются по мере необходимости записи: 2 ГиБ по адресу 16384 на 27B, а `coli plan` оценивает их по 16384. Меньший `Q36_MAXT` отклоняет более длинную запись с именем 422 |

<a id="limits"></a>
## Ограничения

- **Нет изображений.** Клеф читает изображения и видео, но только через свой Python.
  `systemone()`, как изображения PIL; Запрос Джева `/v1/systemone` (оба официальных
  SDK) не имеет поля изображения, как и colibri.
- **Каждый запрос считывает всю запись.** Снимок состояния отсутствует.
  между запросами: второй запрос на тот же документ приносит пользу
  предварительно заполните еще раз.
- **Clef-Flash** (магистраль Qwen3.5-9B, тот же главный код) имеет следующую форму.
  путь ожидает, но здесь не был запущен.
- Чат того же процесса - Qwen3.8-27B с постобученным Клефом
  слои. Работает (спросил на английском про столицу Франции, ответил
  «столица Франции — Париж» на китайском, после логического блока в
  китайский); его качество не было измерено.
