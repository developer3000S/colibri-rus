# Runbook: настоящий GLM-5.2 на этом Mac — хранение, загрузка и путь через M7–M9

Компьютер: M4 Max, 64 ГБ унифицированной памяти, 926 ГБ встроенной памяти NVMe (~365 ГБ свободно по состоянию на
19 июля 2026 г.). Цель разработки тренинга согласно [AGENTS.md](../../../AGENTS.md): RSS для тренера
≤ 52 ГБ, жесткий потолок 56 ГБ, нулевой обмен в устойчивом состоянии.

---

<a id="1-how-much-disk-space-to-free"></a>
## 1. Сколько места на диске освободить

**Цель: ≥ 420 ГиБ бесплатно перед началом загрузки. 450 ГиБ — это комфортно.**

| Товар | Размер |
|---|---|
| GLM-5.2 colibri снимок int4 (головки int8 MTP), измеренный через HF API | **383,8 ГБ = 357,4 ГиБ** (150 файлов) |
| Загрузка slack (частичные файлы во время возобновления работы, метаданные HF-кэша) | ~10 ГиБ |
| Артефакты обучения: токенизированные данные SFT, адаптеры, контрольные точки оптимизатора | < 5 ГиБ (адаптеры — МБ) |
| Передышка APFS + macOS (обмен должен оставаться работоспособным, отток можно очистить) | ~50 ГиБ |

Итак, из сегодняшних ~365 ГиБ бесплатно: **освободите хотя бы еще ~60–90 ГиБ**.

Примечания:
- Альтернативный маршрут (`./coli convert` — потоковая передача FP8 по сегментам, никогда не требуется
  полные 756 ГБ) требуется ~400 ГБ бесплатно *плюс* Python/torch во время конвертации и
  часов процессорного времени. **Предварительно конвертированная загрузка здесь намного лучше**, если только
  зеркало исчезает.
- После того, как модель будет установлена, у вас будет свободно ~35–60 ГиБ. Это осуществимо, но
  тесный; не допускайте попадания на диск каких-либо крупных предметов во время тренировок.

**Перед загрузкой исключите каталог модели из Time Machine и Spotlight**
(в противном случае TM попытается создать резервную копию 358 ГиБ, и Spotlight сожжет процессор, индексируя его):

```bash
mkdir -p ~/Work/models/glm52_i4
tmutil addexclusion ~/Work/models/glm52_i4
mdutil -i off ~/Work/models 2>/dev/null || true   # optional, needs sudo on some setups
```

<a id="2-downloading-the-right-weights"></a>
## 2. Качаем правильные веса

**Используйте предварительно преобразованное зеркало с головками int8 MTP** (это исходное зеркало).
рекомендует; старое зеркало `jlnsrk` имеет головы int4 MTP → 0% спекулятивно
прием):

> https://huggingface.co/mateogrgic/GLM-5.2-colibri-int4-with-int8-mtp

Загрузите вместе с HF-клиентом проекта venv (возобновляемый — безопасно прерывать и
повторный запуск; сделать это за ночь, ~358 ГиБ даже при скорости 40 МБ/с — это ~2,5 часа на 10 GbE, день на
медленные ссылки):

```bash
cd ~/Work/calibri_qlora
.venv/bin/pip install -q -U huggingface_hub
.venv/bin/hf download mateogrgic/GLM-5.2-colibri-int4-with-int8-mtp \
    --local-dir ~/Work/models/glm52_i4
```

**Проверьте перед первым использованием:**

```bash
# 1) MTP heads must be int8 — exactly these sizes (int4 heads = broken MTP):
ls -l ~/Work/models/glm52_i4/out-mtp-*
#   3527131672 / 5366238584 / 1065950496   <- correct (int8)
#   1765523544 / 2686077736 / 536747200    <- WRONG (int4) — re-fetch those 3 files

# 2) read-only readiness check + storage plan (no tensors loaded):
cd ~/Work/calibri_qlora/colibri/c
COLI_MODEL=~/Work/models/glm52_i4 ./coli doctor
COLI_MODEL=~/Work/models/glm52_i4 ./coli plan

# 3) inference smoke — proves the snapshot end-to-end before any training:
COLI_MODEL=~/Work/models/glm52_i4 ./coli chat
```

Место хранения: `~/Work/models/glm52_i4` на внутреннем NVMe (APFS подходит для
путь загрузки; примечание ext4 в исходной документации относится к преобразованию
только маршрут). Внутренний SSD на M4 Max обеспечивает скорость чтения ~5–7 ГБ/с — лучше, чем
большинство внешних корпусов TB, поэтому запуск с внутреннего диска на самом деле является
быстрый вариант, просто малогабаритный.

## 3. Подробный план следующих этапов

### 3а. Проектирование до M7 (все проверено на крошечном оракуле — НЕ требует загрузки,
можно продолжать, пока диск заполняется)

Это закрывает разрыв между «правотой тренера, доказанной в крошечном масштабе» (M0–M6, готово)
и «тренер может прикоснуться к реальному снимку»:

1. **fmt=4 (сгруппированные int4) поддержка в обратном направлении.**
   В реальном снимке некоторые тензоры хранятся как сгруппированные int4 (по 16..256 столбцов).
   весы, `detect_group_size`). `train_qt_bwd_dx` сегодня обрабатывает fmt 0/1/2 и
   выходит на 4. Добавьте сгруппированный путь (сначала процессор, затем вариант `t_tmul` Metal)
   + юнит-тесты по деквантованному эталону, закрытому по типу крошечного прибора
   все остальное.
2. **Менеджер бюджета памяти (AGENTS.md §11).**
   Одна структура, владеющая бюджетом `--ram`: резервирует плотнорезидентные байты,
   адаптер+градация+состояние оптимизатора, обучающая царапина, резерв контрольных точек, ОС
   маржа; *остаток* определяет размер экспертного кэша в **байтах** (сегодняшний слотcount — это миниатюрная модель). Отказывается начинать, если план не подходит.
   Периодическая строка журнала: RSS, пиковый RSS, оценки по категориям, память macOS
   давление + активность подкачки (sysctl/task_info). Запуск с заменой = неудачный запуск.
3. **Тренажер CLI (`coli_train`).**
   `train/train_main.c` двоичный файл: `--model --data --adapter-out --ram 52
   --seq-len 128 --micro-batch 1 --grad-accum 16 --rank 8 --alpha 16
   --привлекает внимание --lr 1e-4 --steps 100 --resume`. Соедините провода вместе
   уже проверенные штуки (model_init с реальными fmts, lora.h, train_model.h
   режим контрольных точек, потоковый экспертный кэш, AdamW). Пошаговые показатели, строка за
   §19: потеря, lr, tok/s (обучение, не только вперед), разделение времени шага
   fwd/bwd/opt/recompute, байты NVMe+время, уникальные эксперты, частота попадания в кэш, RSS.
4. **Конвейер набора данных SFT (§14).**
   `tools/prepare_sft.py`: Чат/завершение JSONL в → шаблоне чата GLM-5.2 через
   токенизатор HF (файлы токенизатора небольшие, их можно загрузить независимо от
   веса) → `train.bin/train.idx/valid.bin/valid.idx/metadata.json`
   (предварительно токенизированные флаги маски подсказки). Считыватель C-стороны `train/dataset.c`:
   детерминированная начальная перетасовка, окна секвенирования, микропакетный итератор. Нет
   упаковка в v1.
5. **Проверка/возобновление (§15).**
   Контрольная точка = адаптер + состояние AdamW + шаг + курсор данных + RNG + конфигурация +
   базовый отпечаток пальца, атомарный tmp→fsync→переименовать. Приемочный тест на крошечном
   модель: 20 непрерывных шагов ≡ 10 шагов → сохранить → перезапустить → 10 шагов
   (тензоры потерь + адаптера совпадают в пределах допуска). Подключено к
   `test_train_tiny` или тест на брата и сестру.
6. **Подготовка к масштабированию в размере `train_model.h`** (бумажный аудит + подтверждение, дешево):
   индексация int64 повсюду при T=128/vocab≈150k/D≈6144, пробники спрятаны
   `[H,T,T]` размер при реальной численности персонала, буфер логитов ~T·V·4 ≈ 78 МБ
   (задокументировано как сохранено), lm_head/embed в реальном словаре.

<a id="3b-milestone-7-real-glm-52-64-gb-smoke-test"></a>
### 3б. Этап 7 — настоящий дымовой тест GLM-5.2 64 ГБ

Предварительные условия: §1+§2 выполнено (модель проверена `coli doctor` + дым в чате),
пункты 1–3 до M7 выполнены (4–5 могут отставать; для дыма достаточно файла синтетического токена).

Конфигурация запуска (вкратце — начните с пола, а не с цели):

```bash
./coli_train \
  --model ~/Work/models/glm52_i4 \
  --data  data/smoke_tokens \
  --adapter-out adapters/m7-smoke \
  --ram 52 --seq-len 128 --micro-batch 1 --grad-accum 4 \
  --rank 4 --alpha 8 --targets attention --lr 1e-4 --steps 10
```

Прогрессия: 1 вперед → 1 вперед+назад → 1 полный шаг оптимизатора → 10 шагов.
На каждом этапе следите за строкой метрики; критерии прерывания сложны:

- RSS > 52 ГБ в устойчивом режиме или *любой* постоянный обмен → остановить, исправить бюджет, повторить;
- неконечная потеря → стоп, разделить пополам слой за слоем вопреки ожиданиям;
- проход слоя, количество уникальных экспертов которого приближается к E → ожидается для обучения
  (риск разветвления, §21) — это проблема *пропускной способности*, а не ошибка; запись
  байт/шаг честно.

Успех = контрольный список §16-M7/§27: нет OOM, нет обмена, RSS под потолком, ограничено
потеря, ненулевое обновление адаптера, контрольная точка загружается обратно в чат `coli
ADAPTER=...`, zero-adapter run still bit-identical, `сделать галочку` по-прежнему зеленой.
Ожидайте однозначных шагов в час с первой попытки — в описании прямо сказано
Сначала осуществимость и правильность, потом пропускная способность (M9).
