# Быстрый старт — с нуля до работающей модели

Пошаговое руководство для начинающих пользователей **Linux**, **Windows** и **macOS**.
Никакого предыдущего опыта работы с C, CUDA или преобразования моделей не предполагается. Если вы получите
застрял, `./coli doctor` (ниже) точно расскажет вам, чего не хватает.

> **Что вы настраиваете:** colibrì использует очень большую модель смешанного состава экспертов.
> (например, параметры GLM-5.2, 744B) на обычной машине путем потоковой передачи данных модели
> Эксперты с диска, а не все в оперативной памяти. Движок один
> Программа C; Python используется только один раз для подготовки файлов модели.

Используете помощника по кодированию с использованием искусственного интеллекта? Попросите его настроить colibri, следуя [docs/AI_SETUP.md](AI_SETUP.md).

<a id="the-one-step-way"></a>
## Одноэтапный способ

**Windows**: скачайте репозиторий (на GitHub: **Код**, затем **Загрузите ZIP**,
и разархивируйте его; или `git clone`), затем дважды щелкните **`START.bat`** в
верхняя папка.

**Linux и macOS:**

```bash
git clone https://github.com/Developer3000S/colibri-rus.git
cd colibri
./start.sh
```

Оба запускают `coli setup`, который делает все остальное:

1. **Находит ваше оборудование**: ОЗУ, свободный диск, на котором установлена модель, характеристики процессора,
   и графические процессоры (любой графический процессор Vulkan с его памятью, карты NVIDIA через nvidia-smi).
2. **Рекомендует подходящую модель** в коротком меню с загрузкой.
   размеры; Enter принимает рекомендацию. «Подходит» означает часть модели.
   который всегда остается в оперативной памяти (плотная часть) плюс минимальный размер экспертного кэша
   в вашей оперативной памяти, а загрузка умещается на вашем диске.
3. **Получает движок**: он собирает его для вашей машины при запуске компилятора.
   там, с помощью Vulkan или CUDA, когда ваш графический процессор может его использовать, или загружает
   готовый, когда нет компилятора (CPU, а в Linux и Windows
   Vulkan тоже). Если пакет отсутствует для
   ваш графический процессор, он печатает точную команду для его установки и продолжает
   CPU; без вас ничего не будет установлено в масштабе всей системы. Запустите установку еще раз
   вы установили его, и он перестраивает движок для графического процессора. CUDA используется
   только тогда, когда установленный набор инструментов CUDA может выполнить сборку для вашей карты: CUDA 13, для
   например, больше не создается для карт Maxwell, Pascal или Volta (V100), поэтому
   там настройка так говорит и использует Vulkan. Если сборка графического процессора все равно не удалась, это
   переходит к следующему (CUDA, затем Vulkan, затем CPU) и сообщает вам, где
   журнал сборки есть.
4. **Загружает модель** с прогрессом и возобновлением. Прерывайте его всякий раз, когда вы
   например: повторный запуск продолжается с того места, где он остановился.
5. **Запускается colibri**, открывается панель управления в браузере и распечатывается
   адреса, которые могут использовать другие приложения.

**Позже:** снова запустите `START.bat` или `./start.sh` и запустится colibri.
сразу, без второй загрузки или сборки. Чтобы остановить его, нажмите Ctrl+C в
его окно или запустите `c/coli stop` с другого терминала (`c\coli.cmd stop` на
Windows). `c/coli status` показывает, что установлено, работает ли оно, его
адреса и скорость последнего ответа. Чтобы выбрать другую модель:
`./start.sh --reconfigure`.

**В WSL** сохраните модель на диске Linux (по умолчанию `~/colibri-models`),
никогда не ниже `/mnt/c`. Если собственная сеть WSL намного медленнее, чем сеть Windows (она может
быть: 63 КБ/с против 3,3 МБ/с было замерено на одной машине), настройка предлагает
загрузить через Windows `curl.exe` в ту же папку.

Полезные опции (`c/coli setup --help` перечислены все): `--yes` занимает каждую
по умолчанию, не спрашивая, `--model ID` выбирает модель (`--list` показывает идентификаторыпротив вашей машины), `--dir DIR` помещает модели в другое место, `--no-gpu` сохраняет
все на CPU, `--backend vulkan` (или `cuda`) выбирает путь к графическому процессору
самостоятельно, `--model-dir DIR` использует уже имеющуюся у вас модель.

### Linux (Ubuntu/Debian)

```bash

```

`build-essential` дает вам `gcc`, `make` и OpenMP (libgomp) — все, что

> **Перенос сборки на другую машину?** Движок связывается с `libgomp.so.1` при запуске.

<a id="2-get-the-code-and-build-the-engine"></a>
## 2. Получите код и создайте движок

```bash
git clone https://github.com/Developer3000S/colibri-rus.git
cd colibri/c
./setup.sh
```

`setup.sh` проверяет ваш компилятор и OpenMP, собирает движок и запускает крошечный
самопроверка. Когда он печатает:

```
engine self-test: 32/32  (expected ~30-32/32; FP near-ties are toolchain-dependent)
```

движок работает правильно. Некоторые цепочки инструментов сообщают о 30/32 или 31/32, потому что
две позиции крошечного оракула представляют собой почти ничьи с плавающей запятой; это все еще актуально
результат самотестирования. (В варианте A Windows у вас уже есть двоичный файл — вы можете
пропустите этот шаг.)

<a id="3-get-the-model"></a>
## 3. Получите модель

У вас есть два пути.

<a id="easiest-download-a-ready-made-int4-container"></a>
### Самый простой — скачать готовый контейнер int4

Предварительно преобразованная модель **GLM-5.2 int4** представлена на Hugging Face. Используйте
**контейнер с масштабированием по группе (gs64)** с **головкой int8 MTP**:

**https://huggingface.co/mastouri/GLM-5.2-colibri-int4-g64-with-int8-mtp**

**GLM-5.3** относится к тому же семейству и имеет тот же движок. Свой собственный
контейнер группового масштабирования (gs64) занимает около **419 ГБ** и поставляется **без** MTP.
head, поэтому спекулятивное декодирование отключено:

**https://huggingface.co/Justvugg/GLM-5.3-colibri-int4-g64**

Групповые масштабы имеют значение: старые контейнеры int4 для каждой строки
(`mateogrgic/…-int4-with-int8-mtp`, `jlnsrk/…`) на ~9 п.п. хуже по качеству
тесты и являются основной причиной циклов режима мышления и бесконечных
поколения в [#455](https://github.com/Developer3000S/colibri-rus/issues/455) —
Контейнер gs64 исправил все случаи сбоя в этом отчете. (Головка MTP int8
также требуется: простые головки int4 отключают спекулятивное декодирование, см.
[#8](https://github.com/Developer3000S/colibri-rus/issues/8).)

Загрузите его в папку на быстром диске, например. `/nvme/glm52_i4` (Linux/macOS) или
`D:\glm52_i4` (Windows). Его объем составляет около **429 ГБ**, поэтому убедитесь, что у вас достаточно места.

Заголовок MTP должен быть **int8, а не int4** (int4 дает 0 % принятия черновика,
[#8](https://github.com/Developer3000S/colibri-rus/issues/8)). Проверьте это с помощью
`ls -l <model>/out-mtp-*`: int8 (правильно) — `3527131672 / 5366238584 / 1065950496`
как три файла или один `out-mtp-00000.safetensors` из `9959321520` байтов
(текущая загрузка рекомендуемого контейнера отправляет его как один файл: то же самое)
int8 тензоров, из них 777 по одному байту на элемент).

<a id="or-convert-it-yourself-from-the-fp8-source"></a>
### Или конвертируйте сами из исходника FP8

Одна возобновляемая команда загружает и преобразует фрагмент модели по фрагменту, поэтому
никогда не нужны все ~756 ГБ на диске сразу:

```bash
./coli convert --model /nvme/glm52_i4
```

В результате создается контейнер группового масштабирования (gs64) — тот же проверенный по качеству
формат, рекомендованный для загрузки. Этот шаг использует Python и выполняется только один раз.
Безопасное прерывание и повторный запуск — он возобновляется с того места, где остановился.

<a id="4-run-it"></a>
## 4. Запустите его

Наведите курсор `COLI_MODEL` на папку из шага 3 и начните общение:

```bash
# Linux / macOS
COLI_MODEL=/nvme/glm52_i4 ./coli chat

# Windows (UCRT64 shell)
COLI_MODEL=/d/glm52_i4 ./coli chat
```

Полезные первые команды:

```bash
COLI_MODEL=/nvme/glm52_i4 ./coli doctor   # read-only check: is everything ready?
COLI_MODEL=/nvme/glm52_i4 ./coli plan     # shows where the model will live (RAM/disk/GPU)
COLI_MODEL=/nvme/glm52_i4 ./coli chat --topp 0.85   # faster: reads less from disk, same quality
```

> **Совет:** `--topp 0.85` стоит добавить на машине с подключенным диском — он читает
> меньше экспертных байтов на токен без потери качества, что напрямую означает больше
> токенов в секунду.

<a id="5-what-to-expect"></a>
## 5. Чего ожидать- **При первом запуске загружаются резидентные веса** (~10 ГБ) — это занимает некоторое время.
- **Скорость зависит от вашего диска.** Эксперты выполняют потоковую передачу из хранилища, поэтому быстрая
  SSD-накопитель NVMe является самым важным фактором в количестве токенов в секунду. На медленном или совместном
  диске, генерация может быть значительно ниже 1 токена в секунду — это ожидаемо, и это
  честная стоимость эксплуатации модели 744B на небольшой машине.
- **Это по-прежнему полная модель.** При размещении меняется только скорость, а не сама модель.
  ответы или точность.

Если что-то не работает, запустите `./coli doctor` — он точно сообщит, что именно.
отсутствуют (компилятор, файлы модели, разрешения) и как это исправить.

<a id="old-processors-no-avx2"></a>
## Старые процессоры (без AVX2)

Движки в архивах релизов и те, которые `coli setup` загружаются при
компилятора нет, созданы для x86-64-v3: используют AVX2, FMA и BMI2.
Процессоры Intel до Haswell (2013 г.) и процессоры AMD до Excavator
(2015) их нет. После версии 2.0.0 движок проверяет это перед запуском и
говорит об этом в одной строке:

```
colibri: this processor has no avx2 fma bmi2, which this engine build needs; ...
```

и `coli setup` называет его в отчете об оборудовании и не устанавливает
готовый движок. Вместо этого более старый движок остановился при первой такой инструкции:
баннер, затем «движок colibri неожиданно выключился» (#1979).

Соберите движки для процессора из клона git (раздел 2):

```bash
cd colibri/c
make qwen36 ARCH=x86-64-v2          # the engine of your model: qwen36, qwen38, glm53, mimo, ...
```

В Windows в оболочке MSYS2 UCRT64 (раздел 1):

```bash
pacman -S --needed git make mingw-w64-ucrt-x86_64-gcc mingw-w64-ucrt-x86_64-libgomp
git clone https://github.com/Developer3000S/colibri-rus
cd colibri/c
make qwen36.exe ARCH=x86-64-v2
```

затем запустите `coli` из этой папки `c` (`python coli web --model ...`). С
компилятор установлен, `coli setup` самостоятельно собирает движок для процессора
(`ARCH=native`).

Сколько это стоит, измерено на Qwen3.6-35B-A3B int4 (та же машина, Ryzen 7
PRO 8700GE, обе сборки, жадные 128 токенов): x86-64-v3 префиллы 13.7 tok/s и
генерирует 8,6 tok/s; x86-64-v2 предварительно заполняет 6.0 tok/s и генерирует 3.6 tok/s, примерно
В 2,4 раза медленнее, с тем же текстом и тем же недоумением. На более старом
процессора оба числа ниже.

`COLI_CPU_CHECK=0` пропускает проверку, в движках и в `coli setup` (ан
эмулятор или гипервизор, который сообщает меньше функций, чем работает).
